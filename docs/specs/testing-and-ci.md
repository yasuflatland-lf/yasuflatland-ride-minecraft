## Rules

### Client entity texture memory

- Applies to: Resource Pack client entity textures and their texture-set companion maps.
- Rule: Collect `description.textures` from every `entity/**/*.ce.json` and the string-valued `metalness_emissive_roughness`, `heightmap` and `normal` companions. Count each distinct pack file once at PNG width x height x 4 bytes. Exclude the two absent vanilla player textures (`steve` and `cape_invisible`), not missing pack assets. The measured total is 197,041,792 bytes (187.913696 MiB); `ENTITY_TEXTURE_BUDGET_BYTES` is 192 MiB. To update the budget, measure again and round up to an 8 MiB multiple, never above 208 MiB. Stop and report measurements above that ceiling in the issue. Reject two files with identical decoded (colour, MER) pixel pairs, or identical MER pixels, regardless of PNG compression. Failures list the ten largest files with decoded MiB. Shared and mirrored regions and separate lit, fixed and paint geometries must preserve sampled texels and byte-identical committed previews.
- Agreement: Accepted
- Basis: [0252](../adr/0252-budget-client-entity-texture-memory.md) Decision; the iPad joined at view-distance 32 with about 162 MiB of scooter textures plus the rest of the pack without crashing.
- Implementation: `tests/packs/textureMemory.test.ts`.
- Verification: `pnpm exec vitest run tests/packs/textureMemory.test.ts` and the normal `pnpm test` suite. Temporarily enlarging one scooter paint texture to 2048 x 2048 must exceed the budget; restore it after checking the diagnostic.

### Generated assets before tests and dev commands

- Applies to: Vitest runs, build, packaging, the dev server, and the in-game driver.
- Rule: Vitest's `tests/support/generatedSetup.ts` runs `python3 -I tools/run_generators.py --ensure` once before test collection, so pack and tool tests can read generated files in a checkout whose generated outputs were deleted. Tests that only need scooter shape read `.cache/generated/scooter_source.geo.json`, the full source geometry written by `gen_scooter.py`. Build invokes the same command before esbuild. The fingerprint stamp in ignored `.cache/generated/stamp.json` skips unchanged inputs with present outputs; ensure skips the preview renderer. `scripts/server-up.mjs` and `scripts/game-test.mjs` call the build when either bundle is missing, source or build inputs are newer, or the runner's read-only `--status` reports stale or missing generated assets. Packaging refuses missing generated outputs, including committed rendered pack textures and icons, with “run `pnpm build` first”. Restore missing renderer outputs or run `pnpm model`; ensure keeps skipping rendering. `pnpm model` forces generation and rendering; `pnpm model:check` ensures fresh packs and checks every generator's output, including the pixels of committed renderings, and output ownership. `tests/tools/renderPreview.test.ts` checks the names and dimensions of the committed camping gear previews and the camper side preview. Untracked manifest outputs are ignored and never committed (0248). Full runner write and `--check` runs collect touched outputs, verify ownership against `tools/generators.json`, and fail on a mismatch before writing a stamp; `--ensure` does not verify ownership.

### Production driving-input receiver

- Applies to: the test pack driving an empty vehicle through the production pack.
- Rule: `TEST_INPUT_EVENT` is `id("test_input")`, hence `yasu_ride:test_input`. The production handler accepts only that id with `sourceType` equal to `ScriptEventSource.Server`. Messages are `<vehicleId>,<moveX>,<moveY>,<jump>` or `<vehicleId>,clear`. The parser requires a nonempty vehicle id, exactly the appropriate field count, nonblank finite movement values, and jump `0` or `1`; it clamps movement to [-1, 1]. Invalid messages warn without replacing stored input. A map keeps the latest input, supports clear, and retains only loaded vehicle ids when the world adapter reads vehicles.
- Agreement: Accepted
- Basis: [0010](../adr/0010-testing-strategy.md) Decision, "The main pack accepts the event only when its `sourceType` is `Server`, rejects values that are not finite, and clamps `moveX` and `moveY` to [-1, 1]."

- Verification: `tests/infrastructure/vehicle/bedrock/subscriptions.test.ts` rejects entity sources and other event ids, preserves input after invalid messages, and clears input; `tests/infrastructure/vehicle/testInput/testInputMessage.test.ts` covers finite values, clamping, blanks, field counts, and jump validation; `tests/infrastructure/vehicle/testInput/vehicleTestStore.test.ts` checks map operations and retain; `tests/infrastructure/vehicle/bedrock/bedrockVehicleWorld.test.ts` checks that unloading a vehicle forgets its input. ### Unit and release workflow layout

- Applies to: pull requests, pushes to main, and tag or manual releases.
- Rule: The unit workflow has `quick`, a two-shard `test` matrix with fail-fast disabled, `tools`, `coverage`, `model-plan`, `model-others`, the per-scene `model-scene` matrix, and the aggregate `check` job. `quick` installs frozen dependencies and runs format, language, docs, and unused-code checks; type, dependency, build, and package checks require `tsconfig.json`. On pull requests the Resource Pack version check runs last and even when an earlier step failed, so a missing bump does not hide the other checks. `check` always runs, needs all seven upstream job ids, prints their results, and requires success except that `model-others` and `model-scene` may be skipped. The release workflow is separate: on a version tag or a manual main run it checks release notes and Resource Pack versioning, installs dependencies, explicitly generates packs, runs typecheck and the unsharded `pnpm test`, builds and packages with the expected tag version, uploads artifacts, and creates the release in a separate job with write permission. It does not repeat every pull-request check.
- Agreement: Accepted
- Basis: [0204](../adr/0204-shard-unit-tests-across-ci-jobs.md) Decision, unit test sharding; [0057](../adr/0057-skip-model-check-when-inputs-unchanged.md) Decision, model check selection and sharding; [0204](../adr/0204-shard-unit-tests-across-ci-jobs.md) Decision, "Keep the required job id `check`."; [0013](../adr/0013-dependency-updates-with-renovate.md) Consequences, "Automerge relies on CI being the gate, so CI must keep covering lint, typecheck, test, and build"
- Implementation: `.github/workflows/unit-test.yml`, `.github/workflows/release.yml`, `package.json`
- Verification: `tests/scripts/checkRpVersion.test.ts` checks Resource Pack version comparison, not release orchestration. Not verified: workflow tests cover model job dependencies and the aggregate gate, but do not exercise live required-status settings, release permissions, or all failure paths. ### Generated output caches and Resource Pack versions

- Applies to: unit, integration, and release workflows.
- Rule: `.github/actions/generated-files` is the single composite action that restores or generates pack files for unit jobs `quick`, `test`, `tools`, `coverage`, `model-others`, and `model-scene`; integration `generate` and `in-game` (which needs `generate`); and release `build`. Callers run it after checkout and toolchain setup, retaining their existing guards. With no inputs, it lists the manifest's untracked outputs, restores those paths and `.cache/generated` through `actions/cache@v6`, and always runs `pnpm generate`. The action alone owns the key `${{ runner.os }}-generated-${{ hashFiles('tools/**', 'mise.toml') }}`; releases can reuse the main cache. Cache-path listing uses Python `-I -B` to keep key inputs unchanged. Generation still validates external inputs and missing outputs after a cache hit. The action exposes `cache-hit` as `'true'` or `'false'` and appends `generated files: cache hit|miss, <N>s` to the job summary, timing `pnpm generate` in seconds. Pull request CI compares Resource Pack versions with the base commit, and releases compare with the previous tag. Tracked RP changes or any generator-input change require a version bump. Declared untracked outputs and Python caches do not count, including generated files deleted from older tags. Untracking build outputs changes no served content by itself; the migration still bumps the Resource Pack version because it lands with generator-input changes.
- Agreement: Proposed
- Basis: [0248](../adr/0248-treat-generated-pack-files-as-build-outputs.md) Decision; [0015](../adr/0015-dev-server-docker-nethernet.md) Decision.
- Implementation: `.github/actions/generated-files/action.yml`; `.github/workflows/unit-test.yml`; `.github/workflows/integration-test.yml`; `.github/workflows/release.yml`; `scripts/check-rp-version.mjs`.
- Verification: `tests/scripts/checkRpVersion.test.ts` checks generator-input-only failures, bumped tracked RP changes, external reads, removed RP files, and ignored build outputs. `tests/tools/generatedOutputs.test.ts` checks shared-action callers, their ordering and guards, that every integration job using the action needs `generate` directly or transitively, bytecode-free cache-path listing, and hit/miss summaries. - Rule: The closed tags are `build`, `camp`, `vehicle`, `vehicle:suv`, `vehicle:camper`, `vehicle:sportsboat`, `vehicle:scooter`, and `vehicle:bulldozer`. A changed `vehicle` covers every kind tag. The first matching impact rule returns all, none, or tags. Harness files and listed external harness imports, shared code, entry/install files, manifests, dependencies, runtime scripts, and server paths select all. Registry-only changes select none; scenario-file tags are the union of catalog entries for that file. Feature folders, motion mappings, and pack stems map to tags; unknown paths or pack stems select all. Docs, tests, remaining scripts/tools, generated scripts, and most Resource Pack changes (including test Resource Pack assets) select none. Resource Pack block models are an earlier exception mapped through pack stems, and `tools/camping_gear.json` maps to camper.
- Agreement: Proposed
- Basis: [0189](../adr/0189-run-only-impacted-in-game-scenarios-locally.md) Decision, "A static, ordered rule table maps each changed path to `all`, `none`, or tags. The first match wins."; [0189](../adr/0189-run-only-impacted-in-game-scenarios-locally.md) Decision, "A changed `vehicle` covers every `vehicle:*` scenario."
- Implementation: `src/test-pack/features.ts`, `src/test-pack/impact.ts` (`IMPACT_RULES`, `HARNESS_IMPORTS`, `MOTION_TAGS`, `PACK_STEM_TAGS`), `src/test-pack/catalog.ts`
- Verification: `tests/test-pack/features.test.ts` checks tag recognition and coverage; `tests/test-pack/impact.test.ts` checks tracked path/stem mappings, harness and scenario imports, literal pack ids, motion reach, unions, monotonic selection, and registry/scenario changes together. The scooter's kind files, pack stems and items map to `vehicle:scooter`. Not verified: static checks do not prove every dynamic or indirect dependency has complete per-scenario tags; no scooter in-game scenario is described here.

### Git base and selection overrides

- Applies to: the Node driver before contacting BDS.
- Rule: Explicit valid `GAME_TEST_FEATURES` overrides diff selection, including when CI or shard settings exist. Otherwise nonempty CI or `GAME_TEST_SHARD`, or exactly `GAME_TEST_ALL=1`, selects the whole suite. Automatic selection uses `git diff --name-only --no-renames <base>` plus untracked files, with base from `GAME_TEST_BASE` or `git merge-base HEAD origin/main`, without fetching. Git failure falls back to all. If no scenario matches the automatically selected features, the command exits successfully before contacting Docker. Selected tags travel in one `features=` token, not as a list of scenario names. By default, a local `pnpm test:game` runs only the scenarios impacted by the diff against the merge base, rather than all scenarios, in `LOCAL_DEFAULT_LANES` lanes (currently 4); `GAME_TEST_ALL=1` selects the whole suite. `GAME_TEST_MANUAL=1` opts into the four decor scenarios marked `manualSetup: true`; the driver sends `manual=1` and both impact planning and the runner honor it. Without opt-in they are skipped before sharding and player checks, with a reason naming `GAME_TEST_MANUAL=1` and their setup note. Opted-in scenarios still require a connected player. `GAME_TEST_ALL=1` does not bypass this gate.
- Agreement: Proposed
- Basis: [0189](../adr/0189-run-only-impacted-in-game-scenarios-locally.md) Decision, "The base is `GAME_TEST_BASE`, or otherwise `git merge-base HEAD origin/main`."; [0189](../adr/0189-run-only-impacted-in-game-scenarios-locally.md) Decision, "A git failure selects everything, and an empty selection exits 0 without contacting the BDS."; [0189](../adr/0189-run-only-impacted-in-game-scenarios-locally.md) Decision, "An explicit `GAME_TEST_FEATURES` wins over the diff."
- Implementation: `scripts/game-test.mjs` (`changedPaths`, `impactedFeatures`), `src/test-pack/impact.ts` (`mustRunAll`, `selectionOf`), `src/test-pack/protocol.ts` (`formatRunRequest`, `defaultLanesOf`, `LOCAL_DEFAULT_LANES`)
- Verification: `tests/test-pack/impact.test.ts` checks full-run environment predicates and pure selection; `tests/test-pack/protocol.test.ts` checks feature token formatting and message limits. Not verified: no test under `tests/scripts/` executes game-test.mjs for git failure, base resolution, Docker avoidance, or explicit-feature precedence.

### Fused courses and engine observations

- Applies to: in-game courses and their pure result helpers.
- Rule: The registry contains fused flight, submarine, parked-camper, bulldozer paving and tool courses, and boat docking and chair courses. `runCourse` executes steps sequentially, converts exceptions to failures, streams executed results, and normally stops after the first failure unless configured otherwise. Aggregate success requires exactly one passing result for each expected step and no unexpected result. Engine scenarios inspect motion, real blocks, properties, components, and timing; the boat-shore loop can stop when `settledAt` observes consecutive speeds below its threshold. Catalog tests enforce declared budgets and registration, not an engine-only assertion policy or a one-vehicle-per-course runtime invariant.
- Agreement: Proposed
- Basis: [0188](../adr/0188-fuse-in-game-scenarios-and-keep-only-engine-facts-in-game.md) Decision, "The course reports each former scenario as a step through `runCourse`."; [0188](../adr/0188-fuse-in-game-scenarios-and-keep-only-engine-facts-in-game.md) Decision, "End fixed waits early once the observed state has settled."; [0188](../adr/0188-fuse-in-game-scenarios-and-keep-only-engine-facts-in-game.md) Decision, "An in-game scenario asserts only what the engine can show: physics, collision, real blocks and permutations, entity components, or engine timing."
- Implementation: `src/test-pack/outcome.ts` (`runCourse`, `outcomeOfSteps`), `src/test-pack/settle.ts`, `src/test-pack/scenarios/index.ts`, `src/test-pack/scenarios/suv.ts`, `src/test-pack/scenarios/camper.ts`, `src/test-pack/scenarios/sportsboat.ts`, `src/test-pack/scenarios/roadPaver.ts`, `src/test-pack/scenarios/camp.ts`
- Verification: `tests/test-pack/outcome.test.ts` checks sequencing, immediate streaming, exceptions, stopping policy, sink failures, missing and duplicate steps; `tests/test-pack/settle.test.ts` checks earliest consecutive completion; `tests/test-pack/catalog.test.ts` checks metadata and registry coverage. `tests/domain/vehicle/kinds/bulldozer/paver.test.ts` covers the build-tool predicate moved out of the game. Not verified: no unit test proves all live assertions are engine-only, preserves every calibration across future edits, or measures actual course ticks and peak vehicles.
