## Rules

### Namespace and pack layout

- Applies to: The build feature shipped inside Yasuflatland Ride.
- Rule: Domain, application, and infrastructure each have a `build` feature. Infrastructure defines `BUILD_NAMESPACE` and `buildId`; the wand, test events, and creative group use `yasu_build:`. Item names use `item.yasu_build:<id>.name`, messages use `yasu_build.message.<name>`, and forms use `yasu_build.form.<name>`. Build item and recipe assets live under `items/yasu_build/` and `recipes/yasu_build/` in the Behavior Pack; the wand texture lives under `textures/items/yasu_build/` in the Resource Pack. Engine-fixed lang and atlas files stay at their standard paths. The copied protection tag remains `yasu_ride:laid`. Pure geometry and state transitions are in the domain; engine permutations, ray reads, particles, and forms are in infrastructure.

### Build mode

- Applies to: A player holding the wand, on foot or riding any vehicle.
- Rule: A tick reads only whether the selected item is the wand. Build mode enters after `BUILD_SPEC.modeEnterTicks` consecutive holding ticks and leaves after `BUILD_SPEC.modeLeaveTicks` consecutive nonholding ticks; returning to the current input resets the streak. A session is created only when the player first holds the wand. Active mode gates preview drawing, not the input handlers or edit jobs. It neither requires a bulldozer nor requests a camera, vehicle visibility, or HUD change. Bootstrap supplies `wantsChaseCamera: () => false` to vehicles and gives build a protection function combining `vehicles.isVehicleSpace` and `camp.isCampSpace`; leaving a vehicle has no build-mode effect.

### Input mapping

- Applies to: Block interaction, attempted block breaking, and item use while holding the wand.
- Rule: The before-event block-break handler cancels every break with the wand held. The block-interaction handler also cancels the event; outside paste aiming it accepts only `isFirstEvent` and defers work through `system.run`. It selects points or confirms the current height; during paste aiming it never pastes. The item-use handler accepts valid wand users through a per-player `PressDebounces` using `BUILD_SPEC.pressDebounceTicks`. Every attempted press updates the last tick, including a rejected repeat, so a continuous held stream is suppressed until a sufficient gap. Outside paste aiming, an aimed block makes item use return because block interaction owns that input. With no aimed block, item use confirms height first, otherwise opens utilities when sneaking or when the flow is idle (`opensUtilityMenu`), otherwise fixes a virtual endpoint. An idle session with no history and no confirmed box has an empty utility menu, so no form opens. In paste aiming it delegates to `PressPasteAim` regardless of sneaking. There is no left-click selection subscriber or gesture-duration detector; any accepted `itemUse`, including a device long press, follows this routing.
- Agreement: Proposed
- Basis: [0198](../adr/0198-one-build-wand-without-a-bulldozer.md) Decision 3, "Debounce a held press, which can repeat `itemUse` every 0.2 seconds, so it counts once."
- Basis: [0203](../adr/0203-build-wand-paste-aiming.md) Decision 3, "`playerInteractWithBlock` never pastes."
- Basis: [0229](../adr/0229-open-build-utilities-with-a-plain-air-press.md) Decision 1, "An air press in `idle` opens the utility menu without sneaking."
- Implementation: `src/infrastructure/build/bedrock/handlers/wand.ts`; `src/domain/build/pressDebounce.ts`; `src/infrastructure/build/install.ts`; `src/application/build/pressPasteAim.ts`

### Point 1, material and lone-corner marker

- Applies to: The first valid block interaction from idle, then the `point1` flow.
- Rule: Point 1 stores the tapped cell, its dimension, and the block permutation's type and states as the sole build material. Starting a new point clears the old confirmed box. Unreadable cells, air, fluids, the generic shulker-box ID, and data-holding kept types are refused as material. Terrain is otherwise eligible. Later endpoints preserve this material. Point selection reports `pointSet`; material naming occurs when choosing a roof/solid or starting a shape edit. The lone marker is the unit cube boundary's eight corners plus twelve edge midpoints, twenty distinct points, using `minecraft:endrod` through the owning player's `spawnParticle`. Preview redraws occur on `BUILD_SPEC.outlineInterval`; the marker appears on alternate redraws. Only the flow's dimension is eligible. Setting the endpoint removes the lone marker, while a separate end-block cube may still use endrod. One point alone cannot build or copy a confirmed selection.
- Agreement: Proposed
- Basis: [0198](../adr/0198-one-build-wand-without-a-bulldozer.md) Decision 4, "The first block tapped is point 1 and its block type is the sole material for the build, even when it is terrain."
- Basis: [0183](../adr/0183-mark-a-lone-selection-corner.md) Decision 2, "The marker is the outline of the corner's unit cube: its eight corners and the midpoint of each of its twelve edges, twenty particles in all."
- Implementation: `src/application/build/setPoint.ts`; `src/domain/build/flow/flow.ts`; `src/domain/build/edit/guard.ts`; `src/domain/build/cornerMarker.ts`; `src/domain/build/preview/preview.ts`; `src/application/build/showPreview.ts`; `src/application/build/confirmShape.ts`; `src/application/build/chooseHeighted.ts`; `src/infrastructure/build/bedrock/bedrockFeedback.ts`

### End-point aiming and virtual point

- Applies to: A selection with point 1 and no fixed endpoint.
- Rule: `BedrockAimReader` reads the head location, view direction, and optional block hit using `maxDistance: BUILD_SPEC.reach`; failures return no aim. A block hit supplies the live endpoint. Otherwise `virtualEndPoint` intersects a vertical plane through the first block's center, normal to the dominant horizontal look axis, with x winning a tie. It floors the coordinates and fixes the normal-axis coordinate to point 1. A nearly parallel ray, intersection behind the origin, or intersection beyond `BUILD_SPEC.reach` gives no virtual point. Preview draws the inclusive bounding-box edges at block centers, thinned by `BUILD_SPEC.outlineMaxPoints`, and the endpoint's unit cube. A second accepted block interaction or air use fixes the endpoint and opens the shape menu. Preview itself does not change the selection.
- Agreement: Proposed
- Basis: [0198](../adr/0198-one-build-wand-without-a-bulldozer.md) Decision 5, "Aimed blocks give the end point; aiming at air gives a virtual point on the vertical plane through point 1 facing the player, snapped to the dominant horizontal look axis."

### Shape derivation and shape menus

- Applies to: A fixed pair of endpoints in `endpoint` flow.
- Rule: Exactly one differing axis gives a line, two give a rectangle, and otherwise the result is a box, including coincident endpoints. Bounds include both endpoints. Line menus offer Place, Fill below, Remove above, Cut, Copy, Rotate, Cancel. Vertical rectangles offer Fill, Frame, Fill below, Remove above, Cut, Copy, Rotate, Cancel. Horizontal rectangles offer Fill, Frame, Gable roof, Hip roof, Cylinder, Sideways cylinder, Sphere, Cube, Fill below, Remove above, Cut, Copy, Rotate, Cancel. Boxes offer Fill, Faces only, Walls only, Cylinder, Sideways cylinder, Sphere, Fill below, Remove above, Cut, Copy, Rotate, Cancel. Frame keeps the rectangle perimeter; Faces only keeps all box boundary faces; Walls only keeps horizontal perimeter columns without floor/ceiling interiors. Thin dimensions with no interior reduce to fill. Replace has no flow, menu entry, use case, or form label. Shape and contents Cancel return to point-1 aiming with the original first point and material. Starting a build confirms the entire bounding box for later Copy before the job runs, even when only its shell is placed or every write is later skipped, and the flow returns to idle. Cut confirms the box too, but enters paste aiming. The selected-box rotation use case turns the entire selected box clockwise by one quarter turn and replaces the endpoint selection with the rotated box while keeping the flow in the same state, dimension and material. An existing confirmed box in that dimension also becomes the rotated box. For source size (sx, sy, sz), `planRotationAboutCenter` sets `target.min.x = source.min.x + trunc((sx - sz) / 2)` and `target.min.z = source.min.z + trunc((sz - sx) / 2)`, with target size (sz, sy, sx) and Y unchanged. The half-cell offset rounds toward zero and negative zero is normalized. Swapping the sizes makes consecutive offsets exact negatives, so two turns, and therefore four, return the original box exactly. Rotate appears after Copy and before Cancel only in endpoint flow. A horizontal rectangle uses the shared Cut/Copy height step, including preview and optional slider, and rotates on height confirmation without a contents menu. Other shapes rotate immediately. Refusal preserves the previous selection or height step. Success keeps the rotated endpoint selected so the shape menu can open again. The union snapshot covers overwritten terrain and neighbors and replaces the previous single Undo entry. The height-step limit and `rotateTooLarge` both measure the union of the old and new boxes.
- Agreement: Proposed
- Basis: [0198](../adr/0198-one-build-wand-without-a-bulldozer.md) Decision 6, "Each menu also offers Cancel, which returns to end-point selection and its preview."
- Basis: [0202](../adr/0202-build-wand-copy-and-continuous-paste.md) Decision 1, "Copy is an entry of the shape menu shown after the end point, before Cancel, for every shape (line, rectangle of any flat axis, box)."
- Basis: [0230](../adr/0230-cut-a-selection-with-the-build-wand.md) Decisions 1 and 2: Cut is offered directly before Copy for every shape, with a shared height step only for horizontal rectangles.
- Implementation: `src/application/build/rotateBox.ts`; `src/domain/build/rotation/rotateBox.ts`; `src/domain/build/session.ts`; `src/application/build/cutBox.ts`; `src/application/build/chooseBoxStep.ts`; `src/application/build/confirmBoxStep.ts`; `src/domain/build/volume/kind.ts`; `src/domain/build/shape/shape.ts`; `src/domain/build/flow/menu.ts`; `src/domain/build/flow/flow.ts`; `src/application/build/confirmShape.ts`; `src/application/build/confirmHeighted.ts`; `src/infrastructure/build/bedrock/menuChoices.ts`

### Roofs

- Applies to: Gable roof or Hip roof chosen on a horizontal rectangle.
- Rule: Roof height grows upward from the inclusive base layer. `maxRoofHeight` caps it at three times the longer footprint dimension and the inclusive `BUILD_SPEC.worldTopY`, with a minimum of one layer. Live aiming uses the nearest point of the forward view ray to the vertical line through the footprint center, rounds the resulting height, and clamps it to that cap. Nearly vertical rays retain the stored `previous` height. Preview computes a height without storing it; confirmation stores the live aimed height. Gable layers narrow across the shorter axis, leaving the ridge along the longer axis; ties run along x. Hip layers narrow on both axes. Full selected-material blocks form stepped layers; an even square retains a symmetric two-by-two top. Fill places all layers; Hollow keeps cells with an exposed face, including a closed bottom and top. After height confirmation the contents menu offers Fill, Hollow, Cancel. The placement count is checked against `BUILD_SPEC.maxVolume` on confirm, not during height aiming.
- Agreement: Proposed
- Basis: [0198](../adr/0198-one-build-wand-without-a-bulldozer.md) Decision 9, "Use stepped full blocks of the selected material, not stairs. After height confirmation, offer Fill or Hollow, the latter a one-block shell."

### Cylinder, cube and shared height step

- Applies to: Cylinder on a horizontal rectangle or box, Cube on a horizontal rectangle, and the shared height-step mechanism.
- Rule: Horizontal rectangles start an unlocked height step; a box Cylinder locks its height to the box and opens contents directly. Solids grow upward and cap height only at `BUILD_SPEC.worldTopY`, with at least one layer; their chosen placement count is limited by `BUILD_SPEC.maxVolume` on confirmation. Cube fills its rectangular bounding prism. Cylinder uses the footprint's centered ellipse: a column is inside when its squared x/z distances divided by the squared half-width/depth sum to at most one. A wall column has a horizontal neighbor outside that ellipse. Fill uses every inside column on every layer; Hollow uses full top/bottom caps and wall columns between; Tube uses only wall columns throughout. Contents are Fill, Hollow, Tube, Cancel. No solid is offered on a line or vertical rectangle, and no Cube is offered on a box. `HeightStepKind` includes roofs, solids, Copy, Cut and Rotate; `volumeOf` supplies height limits/wireframes, while `placementOf` supplies cells/counts only for building kinds. The size action bar updates when preview dimensions change.
- Agreement: Accepted
- Basis: [0201](../adr/0201-build-wand-cylinder-and-cube.md) Decision 4, "The cylinder fits exactly inside the bounding box of the points and stands upright; a non-square box gives an ellipse. The cube fills the bounding box."
- Basis: [0202](../adr/0202-build-wand-copy-and-continuous-paste.md) Decision 10, "The preview, height aim, and slider use the volume; the edit plan and confirm use the placement."
- Implementation: `src/domain/build/volume/`; `src/domain/build/flow/flow.ts`; `src/domain/build/flow/menu.ts`; `src/application/build/chooseHeighted.ts`; `src/application/build/confirmHeighted.ts`; `src/application/build/showPreview.ts`

### Sideways cylinders

- Applies to: Sideways cylinder chosen after Cylinder on boxes or horizontal rectangles; lines and vertical rectangles do not offer it.
- Rule: Read the view ray once when the shape menu response is dispatched. Ignore pitch and choose the dominant horizontal axis by absolute direction components, with x winning ties and unreadable aim falling back to x. Store the choice as `sideCylinderX` or `sideCylinderZ` in the existing height-step kind; later look changes cannot change it. Boxes lock the selected height and open contents directly; horizontal rectangles use the existing height aiming, preview, confirmation and optional slider. Fit an ellipse across the perpendicular horizontal width and the height, allowing one-block cross sections, and extend it along the entire selected axis. Fill places every section cell, Tube only section walls, and Hollow section walls plus filled end caps. Count scans the section once and multiplies by axis length, with at most two cap planes. Use the normal placed-count limit, protections, edit scheduling, confirmed box and Undo. Preview uses dense top and bottom axis lines and sparse end ellipses. Contents offer Fill, Hollow, Tube and Cancel; Cancel returns to point-1 aiming.
- Agreement: Accepted
- Basis: [0233](../adr/0233-round-shapes-and-terrain-operations.md) Decision 2: view-aligned sideways cylinders with retained axes, fitted sections, Fill, Hollow, Tube, existing limits and Undo.

### Sphere

- Applies to: Sphere on a horizontal rectangle or box.
- Rule: A horizontal rectangle starts the unlocked height step; a box locks its height to the box and opens contents directly. Sphere is not offered on a line or vertical rectangle. With size `W, H, D` and doubled center offsets `dx = 2x - minX - maxX` (likewise `dy`, `dz`), a cell is inside only when it is in the box and `dx²/W² + dy²/H² + dz²/D² <= 1`, tested in integers with the denominators cleared. A cube and a box with all odd sides reach the ends of every axis; a non-cube box with an even side may leave an end layer empty. Contents are Fill, Hollow, Cancel. Fill places every inside cell; Hollow places the inside cells with at least one of the six neighbors outside. The placed count is limited by `BUILD_SPEC.maxVolume`, is computed per column so that a large box stays cheap to measure, and Undo restores the cells as for other builds. The height-step outline draws the equator densely and the x-y and z-y ellipses once per block, reducing density to stay within `BUILD_SPEC.outlineMaxPoints`. Above height one, the equator uses at most half the budget so both vertical ellipses remain visible near the top and bottom even on large footprints; they share the remaining points in proportion to their lengths, with at least four samples per vertical ellipse. Height one draws only the equator with the full budget.

### Height-step outline

- Applies to: The particle outline drawn while aiming the height of a roof, Cube, Cylinder, Sideways cylinder, Sphere, or Copy.
- Rule: The outline samples its horizontal top and bottom curves (Cube and Copy edges, both Cylinder ellipses, Sideways cylinder axis lines, the Sphere equator, roof eaves and ridge) `BUILD_SPEC.denseOutlinePerBlock` times per block and every other curve (vertical edges, Cylinder side lines, Sideways cylinder end ellipses, Sphere vertical ellipses, roof hips) once per block. Sphere reserves at least half the budget for its vertical ellipses above height one, as described in the Sphere rule. The start-point and end-point outline is unchanged.

### Remove above

- Applies to: Every shape menu entry `removeAbove` in `endpoint` flow, on every selection shape.
- Rule: The area is the x and z extents of the two points. The lower point's layer stays as the floor, and the job writes air from the next layer through `BUILD_SPEC.worldTopY`, so a raised part inside the area also goes and the floor ends level. The first point's material is ignored, though its existing refusal still applies. Each x and z side may be at most `BUILD_SPEC.maxTerrainSide` (32), inclusive; `maxVolume` does not apply. An over-limit side reports `tooLarge` with the column volume and leaves the flow unchanged. Within the limit the flow becomes `terrainConfirm`; for a nonempty removal range, a form with a body shows the operation, the area size, the height range, that it cannot be undone, and that things above can fall. The displayed upper height is the inclusive top of the player's dimension, read in infrastructure as `dimension.heightRange.max - 1`. The domain removal range still ends at `BUILD_SPEC.worldTopY`, and removal skips unreadable cells. If that domain range is empty or the dimension top is below the first removal layer, the menu skips the form and invokes the existing confirmation logic. The confirmation draws the same outline as `endpoint`. Block and air taps do not change this flow. Cancel, closing the form, and an unanswered form return to point-1 aiming, as shape menu Cancel does. Confirming refuses `busy` and returns to point-1 aiming when an edit runs. Otherwise it confirms the selected box for later Copy, returns the flow to idle, shows `removing`, and starts an `irreversible` job. A floor at the world top skips the confirmation form and goes straight through the same confirmation logic: it first refuses `busy` without changing the confirmed box when an edit runs; otherwise it confirms the selected box, returns to idle, starts no job, and reports `editDoneCount` with 0. The job finishes with `editDoneCount`, adds no history, and takes no Undo hint. Later Undo addresses the previous undoable edit and skips overlapping cells under 0232. Cut's per-cell protections apply, and unsupported things can fall.

### Paste aiming and menu

- Applies to: A clipboard held in `pasteAim`.
- Rule: `ResolvePasteTarget` is shared by preview and press handling; it reads the session clipboard and turn, builds the aimed box, and snaps its minimum Y to one cell above the highest solid ground across its footprint. Each column scans down inclusively from the unsnapped minimum Y (one cell outside the aimed face), for at most `BUILD_SPEC.groundSearchDepth` (64) cells; a footprint wider than 512 columns scans `floor(BUILD_SPEC.groundProbeBudget / columns)` cells (at least one), so one snap reads at most `groundProbeBudget` (32,768) cells. Once a column has ground, later columns scan only above it. The preview reuses the last snap while the unsnapped box and dimension stay the same, for up to `BUILD_SPEC.groundCacheTicks` (20) ticks; a press always re-probes. Air, liquids, and replaceable cover such as grass, flowers, vines and snow layers are skipped. Unloaded or throwing cells make that column groundless. Groundless columns are ignored; if every column is groundless, the preview draws no paste box and a press shows `noGround` and refuses without pasting or opening the menu. X/Z position and size stay unchanged, and the volume extends along positive world axes. A top-face aim on flat ground keeps the original box; wall-side and cave-underside aims drop to the floor below. The aim carries a clockwise quarter turn (0 to 3); odd turns swap X and Z sizes for the target box and outline. Rotate in the Paste menu opens a repeating menu showing the current heading in degrees, with Rotate and Done buttons. Rotate calls `RotatePasteAim` for one clockwise quarter turn and reopens the form with the new heading. Done, Escape, or cancellation closes it and keeps the turn; leaving paste aiming or disconnecting stops the loop. There are no new key bindings or sneak actions. The anchor is the snapped box minimum, and the engine places the rotated structure with its minimum corner at that anchor. The turn persists across successive pastes while aiming. New copy, End pasting, and completing a new copy reset it to no turn. An absent block hit gives no outline; an accepted item use then opens the paste menu without requiring sneak. With a hit, accepted item use pastes at the live target, independently of the last outline. The blue `minecraft:blue_flame_particle` outline redraws on `BUILD_SPEC.outlineInterval`; the action bar refreshes clipboard dimensions and block count (the box volume) on that interval even without a hit. The paste menu opens only when the aim has no block hit; a press without a clipboard shows `noClipboard`. Its order is Undo when history exists, Rotate, New copy, End pasting. Paste replaces the whole target box with the clipboard structure, including air, block entity contents and eligible entities, as the rule "Edit protections and limits" describes; there is no Skip air toggle. New copy clears the selection and returns to idle while retaining the old clipboard; selection, Clear selection, cancellation, and oversized-copy refusal keep it until a successful replacement or exit. No paste outline or hint is shown during that selection. End pasting discards clipboard and confirmed box and returns to idle. Successful or refused pastes otherwise retain aiming.

### Edit protections and limits

- Applies to: Shape, roof, solid, Cut, Remove above, Fill below, paste, selected-box rotation, and undo in every game mode.
- Rule: Before writing each planned cell, `EditJobs` reads its current permutation and skips unreadable cells, kept types, cells denied by `mayEdit`, and unchanged states. `mayEdit` denies bootstrap-protected vehicle/camp space, laid-tagged blocks, unavailable blocks, and engine read failures. Build kept types are `PLACE_KEPT_BLOCKS` plus `BUILD_KEPT_BLOCKS` (sign variants, spawners, vault, command-block variants, structure block and jigsaw); air and fluids are writable. Kept types protect only cell jobs (shapes, roofs, solids, Remove above, Fill below and cell Undo). Paste preflights every cell of its entire target box with `mayEdit`; one failure refuses the whole paste as `pasteBlocked`. Containers and other kept types do not protect a paste. Paste refuses a busy session, captures a Memory undo snapshot of the target box (a refusal reports `pasteFailed`), removes non-player entities there except this addon's vehicles, and places the clipboard structure at the anchor. If placement fails, it removes entities again, places the snapshot back, discards it, reports `pasteFailed`, and keeps earlier history. Paste runs synchronously without `EditJobs`; on success it records the snapshot, reports the box volume, and moves the owner out of solid cells with the shared escape behavior. Shape and heighted edits limit the actual style's planned cell count to `BUILD_SPEC.maxVolume`; a large hollow bounding box can therefore be accepted. Cut limits the entire bounding volume to `BUILD_SPEC.maxCopyVolume`, refuses busy sessions, and preflights every cell with `mayEdit`; any denial refuses the whole cut with `pasteBlocked`. Containers and other kept types do not protect a cut. Both clipboard and snapshot captures must succeed before any removal; refusals preserve flow, confirmed box, clipboard and history and discard newly captured handles. Before changing session state, Cut removes non-player entities and clears every block to air without drops, including containers, signs and fluids; this addon's vehicles are neither copied nor removed. External fluids may flow back afterward. Cut runs synchronously without `EditJobs`. After clearing succeeds, it replaces the clipboard and records one snapshot, discarding the previous structure clipboard and older snapshot handles, and reports the full volume. If clearing fails, it places the snapshot at the source minimum to restore blocks and removed entities. Successful rollback discards both new handles, leaves clipboard, history, selection and flow unchanged, logs a warning, reports `cutRestored`, and returns false. If rollback also fails, Cut retains the snapshot in history, replaces the clipboard and enters paste aiming, logs a warning, reports `cutIncomplete` without an undo hint, and returns true so Undo can restore the area. Snapshot Undo restores the whole source box, including contents and eligible entities; it does not restore the previous clipboard. Selected-box rotation first limits the union of the source and target boxes to `BUILD_SPEC.maxCopyVolume`, then refuses a busy session, then checks `mayEdit` on every union cell; a denial reports `rotateBlocked` without changing anything. Target cells outside the source are overwritten, including terrain, water and neighboring blocks. It captures the union snapshot before the source structure; either capture refusal reports `rotateTooLarge` and discards new handles. It clears eligible entities and all blocks in the source, then places the source at the rotated target minimum with turn 1. Failed clearing or placement attempts restoration by clearing eligible union entities and placing the snapshot at the union minimum, discards both handles, logs a warning and reports `rotateFailed`, preserving selection and earlier history. Success records the union snapshot, discards the source handle, updates the selection, moves the owner out of solid target cells with the shared escape behavior, and reports `rotateDone` with the source volume. Excluded `yasu_ride:` and `yasu_build:` entities stay where they are. Undo restores the whole union, including cells the target grew into. The single snapshot slot means rotation replaces an earlier paste or cut undo and discards its handle. Cell jobs share `BUILD_SPEC.blocksPerTick` planned-cell budget, round robin, and do not read game mode or consume/return inventory. Failed writes are skipped, not rolled back. Protections are rechecked as the job runs.

### Continuous paste and undo

- Applies to: Per-player edit scheduling, repeat suppression and history.
- Rule: Each session allows one running edit; another edit reports busy and is not queued. `PasteAt` first ignores the same anchor within `BUILD_SPEC.pasteRepeatTicks`, then checks protection, then busy state. Already-reverted cells equal to before are left alone without being counted as skipped. Cells differing from both states are conflicts and remain unchanged. Cell Undo shows `undoDone` when none were skipped, otherwise `undoDonePartial` with restored and skipped counts; it adds no redo record. The first nonempty undoable edit in each session that finishes in such a state also sends the chat line "Made a mistake? Long-press the air with the wand and choose Undo." Empty edits, undo, and edits that finish where the gesture is not true never consume or show the chat hint. The hint resets when the session is removed on disconnect or reload. Undo takes the newest entry of either kind. Snapshot undo first checks `mayRestore` for every cell of its recorded box (space protection only; laid-tagged blocks do not block it, because a structure paste may have placed them). Any space-protected cell reports `pasteBlocked` and puts the entry back unchanged for retry, without calling the structure store. Successful restoration includes containers and eligible entities, clears the last paste marker, and reports `undoDone` with the box volume, retaining the clipboard and paste aiming. ### Automatic escape after an edit

- Applies to: Every successfully completed edit job, including shapes, solids, Paste, Undo, and irreversible edits.

### Fill below

- Applies to: Every selection shape, through Fill below immediately before Remove above.
- Rule: Use the selected x/z extents, each at most `BUILD_SPEC.maxTerrainSide` (32), and the higher selected Y as the inclusive top. For an oversized footprint, report the bounding prism count from the world floor through the higher selected Y. Refuse listed falling or support-dependent materials at menu choice with `fillMaterialRefused`, preserving the endpoint flow. Confirm the operation, footprint, bottom and top height, warning that it cannot be undone; cancellation returns to aiming. The displayed bottom is the inclusive minimum of the player's dimension, read in infrastructure as `dimension.heightRange.min`. The domain planning bound remains `BUILD_SPEC.worldBottomY`; unreadable cells below the dimension floor are barriers. Seed every fillable top-layer cell and follow six-neighbor paths, including upward paths behind overhangs, down to `BUILD_SPEC.worldBottomY` (-64). Air and liquids are fillable; unreadable cells, solids and `mayEdit` refusals are barriers. Never write outside the selected x/z bounds or above the top; disconnected cavities stay untouched. Each planning read occurs at most once, with a `SCAN_STEP` consuming one job-budget step; each proposed write consumes another. A `Uint8Array` stores visited marks before reads, and a numeric index stack holds pending cells. The maximum prism has 393,216 marks and at most 786,432 read/write steps, approximately ten seconds at 4,096 steps per tick and 20 ticks per second. The job confirms the original selected box for Copy, uses no history and count-only completion, preserves earlier Undo history, and uses the shared owner escape behavior. Selecting a slope can leave a cliff at the boundary; a player in an outside side passage may be trapped and is not moved because their cells were not written.
