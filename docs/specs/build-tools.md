## Rules

### Namespace and pack layout

- Applies to: The build feature shipped inside Yasuflatland Ride.
- Rule: Domain, application, and infrastructure each have a `build` feature. Infrastructure defines `BUILD_NAMESPACE` and `buildId`; the wand, test events, and creative group use `yasu_build:`. Item names use `item.yasu_build:<id>.name`, messages use `yasu_build.message.<name>`, and forms use `yasu_build.form.<name>`. Build item and recipe assets live under `items/yasu_build/` and `recipes/yasu_build/` in the Behavior Pack; the wand texture lives under `textures/items/yasu_build/` in the Resource Pack. Engine-fixed lang and atlas files stay at their standard paths. The copied protection tag remains `yasu_ride:laid`. Pure geometry and state transitions are in the domain; engine permutations, ray reads, particles, and forms are in infrastructure.

### Build mode

- Applies to: A player holding the wand, on foot or riding any vehicle.
- Rule: A tick reads only whether the selected item is the wand. Build mode enters after `BUILD_SPEC.modeEnterTicks` consecutive holding ticks and leaves after `BUILD_SPEC.modeLeaveTicks` consecutive nonholding ticks; returning to the current input resets the streak. A session is created only when the player first holds the wand. Active mode gates preview drawing, not the input handlers or edit jobs. It neither requires a bulldozer nor requests a camera, vehicle visibility, or HUD change. Bootstrap supplies `wantsChaseCamera: () => false` to vehicles and gives build a protection function combining `vehicles.isVehicleSpace` and `camp.isCampSpace`; leaving a vehicle has no build-mode effect.

### Input mapping

- Applies to: Block interaction, attempted block breaking, and item use while holding the wand.
- Rule: The before-event block-break handler cancels every break with the wand held. The block-interaction handler also cancels the event; outside paste aiming it accepts only `isFirstEvent` and defers work through `system.run`. It selects points or confirms the current height; during paste aiming it never pastes. The item-use handler accepts valid wand users through a per-player `PressDebounces` using `BUILD_SPEC.pressDebounceTicks`. Every attempted press updates the last tick, including a rejected repeat, so a continuous held stream is suppressed until a sufficient gap. Outside paste aiming, an aimed block makes item use return because block interaction owns that input. With no aimed block, item use confirms height first, otherwise opens utilities when sneaking or when the flow is idle (`opensUtilityMenu`), otherwise fixes a virtual endpoint. An idle session with no history and no confirmed box has an empty utility menu, so no form opens. In paste aiming it delegates to `PressPasteAim` regardless of sneaking. There is no left-click selection subscriber or gesture-duration detector; any accepted `itemUse`, including a device long press, follows this routing.
- Agreement: Proposed
- Basis: [0198](../adr/0198-one-build-wand-without-a-bulldozer.md) Decision 3, "Debounce a held press, which can repeat `itemUse` every 0.2 seconds, so it counts once."
- Basis: [0203](../adr/0203-build-wand-paste-aiming.md) Decision 3, "`playerInteractWithBlock` never pastes."
- Basis: [0229](../adr/0229-open-build-utilities-with-a-plain-air-press.md) Decision 1, "An air press in `idle` opens the utility menu without sneaking."
- Implementation: `src/infrastructure/build/bedrock/handlers/wand.ts`; `src/domain/build/pressDebounce.ts`; `src/infrastructure/build/install.ts`; `src/application/build/pressPasteAim.ts`

### Point 1, material and lone-corner marker

- Applies to: The first valid block interaction from idle, then the `point1` flow.
- Rule: Point 1 stores the tapped cell, its dimension, and the block permutation's type and states as the sole build material. Starting a new point clears the old confirmed box. Unreadable cells, air, fluids, the generic shulker-box ID, and data-holding kept types are refused as material. Terrain is otherwise eligible. Later endpoints preserve this material. Point selection reports `pointSet`; material naming occurs when choosing a roof/solid or starting a shape edit. The lone marker is the unit cube boundary's eight corners plus twelve edge midpoints, twenty distinct points, using `minecraft:endrod` through the owning player's `spawnParticle`. Preview redraws occur on `BUILD_SPEC.outlineInterval`; the marker appears on alternate redraws. Only the flow's dimension is eligible. Setting the endpoint removes the lone marker, while a separate end-block cube may still use endrod. One point alone cannot build or copy a confirmed selection.
- Agreement: Proposed
- Basis: [0198](../adr/0198-one-build-wand-without-a-bulldozer.md) Decision 4, "The first block tapped is point 1 and its block type is the sole material for the build, even when it is terrain."
- Basis: [0183](../adr/0183-mark-a-lone-selection-corner.md) Decision 2, "The marker is the outline of the corner's unit cube: its eight corners and the midpoint of each of its twelve edges, twenty particles in all."
- Implementation: `src/application/build/setPoint.ts`; `src/domain/build/flow/flow.ts`; `src/domain/build/edit/guard.ts`; `src/domain/build/cornerMarker.ts`; `src/domain/build/preview/preview.ts`; `src/application/build/showPreview.ts`; `src/application/build/confirmShape.ts`; `src/application/build/chooseHeighted.ts`; `src/infrastructure/build/bedrock/bedrockFeedback.ts`

### End-point aiming and virtual point

- Applies to: A selection with point 1 and no fixed endpoint.
- Rule: `BedrockAimReader` reads the head location, view direction, and optional block hit using `maxDistance: BUILD_SPEC.reach`; failures return no aim. A block hit supplies the live endpoint. Otherwise `virtualEndPoint` intersects a vertical plane through the first block's center, normal to the dominant horizontal look axis, with x winning a tie. It floors the coordinates and fixes the normal-axis coordinate to point 1. A nearly parallel ray, intersection behind the origin, or intersection beyond `BUILD_SPEC.reach` gives no virtual point. Preview draws the inclusive bounding-box edges at block centers, thinned by `BUILD_SPEC.outlineMaxPoints`, and the endpoint's unit cube. A second accepted block interaction or air use fixes the endpoint and opens the shape menu. Preview itself does not change the selection.
- Agreement: Proposed
- Basis: [0198](../adr/0198-one-build-wand-without-a-bulldozer.md) Decision 5, "Aimed blocks give the end point; aiming at air gives a virtual point on the vertical plane through point 1 facing the player, snapped to the dominant horizontal look axis."

### Shape derivation and shape menus

- Applies to: A fixed pair of endpoints in `endpoint` flow.
- Rule: Exactly one differing axis gives a line, two give a rectangle, and otherwise the result is a box, including coincident endpoints. Bounds include both endpoints. Line menus offer Place, Copy, Cancel. Vertical rectangles offer Fill, Frame, Copy, Cancel. Horizontal rectangles offer Fill, Frame, Gable roof, Hip roof, Cylinder, Cube, Copy, Cancel. Boxes offer Fill, Faces only, Walls only, Cylinder, Copy, Cancel. Frame keeps the rectangle perimeter; Faces only keeps all box boundary faces; Walls only keeps horizontal perimeter columns without floor/ceiling interiors. Thin dimensions with no interior reduce to fill. Replace has no flow, menu entry, use case, or form label. Shape and contents Cancel return to point-1 aiming with the original first point and material. Starting a build confirms the entire bounding box for later Copy before the job runs, even when only its shell is placed or every write is later skipped, and the flow returns to idle.

### Roofs

- Applies to: Gable roof or Hip roof chosen on a horizontal rectangle.
- Rule: Roof height grows upward from the inclusive base layer. `maxRoofHeight` caps it at three times the longer footprint dimension and the inclusive `BUILD_SPEC.worldTopY`, with a minimum of one layer. Live aiming uses the nearest point of the forward view ray to the vertical line through the footprint center, rounds the resulting height, and clamps it to that cap. Nearly vertical rays retain the stored `previous` height. Preview computes a height without storing it; confirmation stores the live aimed height. Gable layers narrow across the shorter axis, leaving the ridge along the longer axis; ties run along x. Hip layers narrow on both axes. Full selected-material blocks form stepped layers; an even square retains a symmetric two-by-two top. Fill places all layers; Hollow keeps cells with an exposed face, including a closed bottom and top. After height confirmation the contents menu offers Fill, Hollow, Cancel. The placement count is checked against `BUILD_SPEC.maxVolume` on confirm, not during height aiming.
- Agreement: Proposed
- Basis: [0198](../adr/0198-one-build-wand-without-a-bulldozer.md) Decision 9, "Use stepped full blocks of the selected material, not stairs. After height confirmation, offer Fill or Hollow, the latter a one-block shell."
- Implementation: `src/domain/build/roof/roof.ts`; `src/domain/build/roof/geometry.ts`; `src/domain/build/aim/aim.ts`; `src/domain/build/aim/height.ts`; `src/application/build/aimHeight.ts`; `src/application/build/showPreview.ts`; `src/application/build/confirmHeighted.ts`

### Cylinder, cube and shared height step

- Applies to: Cylinder on a horizontal rectangle or box, Cube on a horizontal rectangle, and the shared height-step mechanism.
- Rule: Horizontal rectangles start an unlocked height step; a box Cylinder locks its height to the box and opens contents directly. Solids grow upward and cap height only at `BUILD_SPEC.worldTopY`, with at least one layer; their chosen placement count is limited by `BUILD_SPEC.maxVolume` on confirmation. Cube fills its rectangular bounding prism. Cylinder uses the footprint's centered ellipse: a column is inside when its squared x/z distances divided by the squared half-width/depth sum to at most one. A wall column has a horizontal neighbor outside that ellipse. Fill uses every inside column on every layer; Hollow uses full top/bottom caps and wall columns between; Tube uses only wall columns throughout. Contents are Fill, Hollow, Tube, Cancel. No solid is offered on a line or vertical rectangle, and no Cube is offered on a box. `HeightStepKind` includes roofs, solids, and Copy; `volumeOf` supplies height limits/wireframes, while `placementOf` supplies cells/counts only for building kinds. The size action bar updates when preview dimensions change.
- Agreement: Accepted
- Basis: [0201](../adr/0201-build-wand-cylinder-and-cube.md) Decision 4, "The cylinder fits exactly inside the bounding box of the points and stands upright; a non-square box gives an ellipse. The cube fills the bounding box."
- Basis: [0202](../adr/0202-build-wand-copy-and-continuous-paste.md) Decision 10, "The preview, height aim, and slider use the volume; the edit plan and confirm use the placement."
- Implementation: `src/domain/build/volume/`; `src/domain/build/flow/flow.ts`; `src/domain/build/flow/menu.ts`; `src/application/build/chooseHeighted.ts`; `src/application/build/confirmHeighted.ts`; `src/application/build/showPreview.ts`

### Height-step outline

- Applies to: The particle outline drawn while aiming the height of a roof, Cube, Cylinder, or Copy.
- Rule: The outline samples its horizontal top and bottom curves (Cube and Copy edges, both Cylinder ellipses, roof eaves and ridge) `BUILD_SPEC.denseOutlinePerBlock` times per block and every other curve (vertical edges, Cylinder side lines, roof hips) once per block. When the dense curves alone exceed `BUILD_SPEC.outlineMaxPoints` they share it in proportion to their length and the other curves get none; otherwise the other curves share what is left. The start-point and end-point outline is unchanged.
- Agreement: Proposed
- Basis: [0228](../adr/0228-dense-horizontal-edges-in-the-height-step-outline.md) Decision 1, "Sample the horizontal curves at the top and bottom of the shape four times per block, so the top reads as a continuous ring."
- Implementation: `src/domain/build/wireframe.ts`; `src/domain/build/volume/cube.ts`; `src/domain/build/volume/cylinder.ts`; `src/domain/build/roof/geometry.ts`
- Verification: Property and example tests in `tests/domain/build/cube.test.ts` and `tests/domain/build/cylinder.test.ts` check the budget, edge placement, density, and that vertical samples are dropped first. Not verified: how the height reads on a client, or particle load on mobile.

### Copy

- Applies to: Shape-menu Copy or selection-utility Copy of a confirmed box.
- Rule: Shape-menu Copy on a horizontal rectangle starts an upward Copy height step using the Cube volume and `BUILD_SPEC.worldTopY`; confirmation copies immediately without a contents menu. Other shapes copy their inclusive bounding box directly. Utility Copy reads the confirmed box in its recorded dimension. A copy exceeding bounding-box volume `BUILD_SPEC.maxCopyVolume` reports too large and preserves flow, confirmed box, and any old clipboard. Copy reads synchronously, storing type/state permutations at offsets from the box minimum. Unreadable and kept-type cells are omitted, leaving holes on paste; ordinary air is retained. It does not serialize block-entity contents or change inventory. Copy height preview uses `minecraft:balloon_gas_particle`, switching to `minecraft:redstone_wire_dust_particle` above the copy limit, separately from build and paste layers. It retains the size readout. Success replaces the clipboard and confirmed box, reports stored cell count, and enters `pasteAim` with Skip air off; no block tap or utility Paste entry is needed.
- Agreement: Proposed

### Paste aiming and menu

- Applies to: A clipboard held in `pasteAim`.
- Rule: `aimedPasteTarget` is shared by preview and press handling. It places the clipboard minimum one cell outside the viewed block's face, with the volume extending along positive world axes and no rotation. An absent block hit gives no outline; an accepted item use then opens the paste menu without requiring sneak. With a hit, accepted item use pastes at the live target, independently of the last outline. The blue `minecraft:blue_flame_particle` outline redraws on `BUILD_SPEC.outlineInterval`; the action bar refreshes clipboard dimensions and stored cell count on that interval even without a hit. The paste menu order is Undo when history exists, Skip air with on/off state, New copy, End pasting. Skip air defaults to off on every successful Copy, persists across pastes, and affects only subsequently created plans. New copy clears the selection and returns to idle while retaining the old clipboard; selection, Clear selection, cancellation, and oversized-copy refusal keep it until a successful replacement or exit. No paste outline or hint is shown during that selection. End pasting discards clipboard and confirmed box and returns to idle. Successful or refused pastes otherwise retain aiming.
- Agreement: Proposed
- Basis: [0203](../adr/0203-build-wand-paste-aiming.md) Decision 4, "A long press on air opens, without sneaking, a menu in this order: Undo when history exists, Skip air with its on/off state, New copy, and End pasting."

### Edit protections and limits

- Applies to: Shape, roof, solid, paste, and undo jobs in every game mode.
- Rule: Before writing each planned cell, `EditJobs` reads its current permutation and skips unreadable cells, kept types, cells denied by `mayEdit`, and unchanged states. `mayEdit` denies bootstrap-protected vehicle/camp space, laid-tagged blocks, unavailable blocks, and engine read failures. Build kept types are `PLACE_KEPT_BLOCKS` plus `BUILD_KEPT_BLOCKS` (sign variants, spawners, vault, command-block variants, structure block and jigsaw); air and fluids are writable. Paste preflight checks every cell of its entire bounding box with `mayEdit`, including holes and skipped air; one failure refuses the whole paste as `pasteBlocked`. Kept types are checked only during per-cell application, so their presence alone does not refuse an entire paste. Shape and heighted edits limit the actual style's planned cell count to `BUILD_SPEC.maxVolume`; a large hollow bounding box can therefore be accepted. Copy instead limits bounding volume to `BUILD_SPEC.maxCopyVolume`. Jobs share `BUILD_SPEC.blocksPerTick` planned-cell budget, round robin, and do not read game mode or consume/return inventory. Failed writes are skipped, not rolled back. Protections are rechecked as the job runs.
- Agreement: Proposed
- Basis: [0178](../adr/0178-bulldozer-build-tools-in-a-separate-namespace.md) Decision 6, "Edits never touch cells that `isVehicleSpace` or `isCampSpace` claims (passed in through bootstrap), blocks tagged `yasu_ride:laid`, or blocks that hold data"
- Basis: [0198](../adr/0198-one-build-wand-without-a-bulldozer.md) Decision 11, "Fill, hollow, roof, and paste take no inventory blocks, and undo returns none, in every game mode."
- Implementation: `src/domain/shared/keptBlocks.ts`; `src/domain/build/edit/guard.ts`; `src/domain/build/edit/plan.ts`; `src/application/build/confirmShape.ts`; `src/application/build/confirmHeighted.ts`; `src/application/build/pasteAt.ts`; `src/application/build/editJobs.ts`; `src/infrastructure/build/bedrock/bedrockBlockWorld.ts`; `src/infrastructure/bootstrap.ts`
- Verification: `tests/domain/build/edit.test.ts`, `tests/domain/build/keptBlocks.test.ts`, `tests/application/build/edits.test.ts`, and `tests/infrastructure/build/bedrock.test.ts` inspect filtering, unreadable cells, budgets and engine write failure. ### Continuous paste and undo

- Applies to: Per-player edit scheduling, repeat suppression and history.
- Rule: Each session allows one running edit; another edit reports busy and is not queued. `PasteAt` first ignores the same anchor within `BUILD_SPEC.pasteRepeatTicks`, then checks protection, then busy state. A refused paste never records a repeat window. A successful start records the anchor/tick and captures the current Skip air setting. Each completed nonempty edit records only successfully changed cells, including exact before/after permutations and dimension, up to `BUILD_SPEC.undoDepth` newest records. Empty edits add no history. Undo removes the newest record, plans its before states in reverse order in the recorded dimension, and uses the same protection/write path; it adds no redo record. Undo retains clipboard and paste aiming and clears the same-anchor repeat window. Ending paste or switching items leaves an already running job able to finish and record history while the session exists.
- Agreement: Proposed
- Basis: [0203](../adr/0203-build-wand-paste-aiming.md) Decision 7, "A second press on the same anchor within `BUILD_SPEC.pasteRepeatTicks` (10) is ignored; a refused paste does not start that window."
- Basis: [0203](../adr/0203-build-wand-paste-aiming.md) Decision 4, "Undo reverts the last paste, keeps the clipboard and paste aiming, and clears the same-anchor repeat window."
- Implementation: `src/application/build/pasteAt.ts`; `src/application/build/editJobs.ts`; `src/application/build/undoEdit.ts`; `src/domain/build/edit/change.ts`; `src/domain/build/history/history.ts`; `src/domain/build/flow/paste.ts`; `src/domain/build/flow/flow.ts`; `src/domain/build/session.ts`

### Session lifetime

- Applies to: Selection flow, confirmed box, clipboard, history, debounce and queued jobs.
- Rule: `InMemorySessionRepository` keeps one session per player ID; reload loses all state. Disconnect removes the session and debounce; a job whose session no longer exists is dropped on its next step. Death and dimension change invoke End pasting in every flow, clearing selection, clipboard and confirmed box while retaining history and the session. They do not reset debounce or cancel a running job. Leaving active build mode after the item grace delay clears a non-idle flow or any held clipboard, including during New copy. A completed build's confirmed box survives an item switch when the session is idle and has no clipboard; a new point 1 or Clear selection removes it. End pasting and New copy also clear the confirmed box, as specified in their flows.
- Agreement: Proposed
- Basis: [0178](../adr/0178-bulldozer-build-tools-in-a-separate-namespace.md) Decision 10, "Selections, clipboards, and undo history live in memory per player and are lost on reload or when the player leaves."
- Basis: [0203](../adr/0203-build-wand-paste-aiming.md) Decision 5, "End pasting, switching items after `modeLeaveTicks` (6), death, and a dimension change end paste aiming and discard the clipboard and confirmed box."
- Implementation: `src/infrastructure/build/persistence/inMemorySessionRepository.ts`; `src/infrastructure/build/bedrock/handlers/sessions.ts`; `src/application/build/updateBuildModes.ts`; `src/application/build/leaveBuild.ts`; `src/application/build/editJobs.ts`; `src/domain/build/session.ts`

### Menus via server-ui

- Applies to: Shape, contents, normal utilities, paste utilities, and optional height slider forms.
- Rule: Infrastructure uses `ActionFormData` for action menus and `ModalFormData` for the height fallback. `BUILD_SPEC.heightSliderFallback` is false; when enabled, an unlocked height-step choice opens an integer slider from one to the kind's maximum, seeded by the previous height. Copy confirms immediately after that slider; building kinds open contents. A locked box Cylinder bypasses the slider. Normal utilities open with sneaking or a plain air press while idle, and contain Copy only with a confirmed box, Undo only with history, and Clear selection only with a current flow or confirmed box; no Paste, Stop pasting or pre-paste toggle form remains. One per-player lock spans nested forms, and responses are dispatched only if the choice is offered by the current flow. Shape/contents dismissal maps to Cancel; utility/paste dismissal has no action. Form failures are caught and release the lock. All form/message keys exist in both English and Japanese lang files. The Behavior Pack pins stable `@minecraft/server-ui` 2.0.0 and `@minecraft/server` 2.2.0. Its Resource Pack dependency matches the Resource Pack header/module version, and the reciprocal Behavior Pack version matches too.
- Agreement: Proposed
- Basis: [0198](../adr/0198-one-build-wand-without-a-bulldozer.md) Decision 6, "Use stable `@minecraft/server-ui` ActionForms and offer only actions that apply"
- Basis: [0203](../adr/0203-build-wand-paste-aiming.md) Decision 9, "The normal selection utility menu keeps Copy of the confirmed box, Undo, and Clear selection."
- Basis: [0229](../adr/0229-open-build-utilities-with-a-plain-air-press.md) Consequences, "An idle session with no history and no confirmed box has an empty utility menu, so the press opens no form."
