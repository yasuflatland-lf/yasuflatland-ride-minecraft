## Rules

### Namespace and pack layout

- Applies to: The build feature shipped inside Yasuflatland Ride.
- Rule: Domain, application, and infrastructure each have a `build` feature. Infrastructure defines `BUILD_NAMESPACE` and `buildId`; the wand, test events, and creative group use `yasu_build:`. Item names use `item.yasu_build:<id>.name`, messages use `yasu_build.message.<name>`, and forms use `yasu_build.form.<name>`. Build item and recipe assets live under `items/yasu_build/` and `recipes/yasu_build/` in the Behavior Pack; the wand texture lives under `textures/items/yasu_build/` in the Resource Pack. Engine-fixed lang and atlas files stay at their standard paths. The copied protection tag remains `yasu_ride:laid`. Pure geometry and state transitions are in the domain; engine permutations, ray reads, particles, and forms are in infrastructure.

### Build mode

- Applies to: A player holding the wand, on foot or riding any vehicle.
- Rule: A tick counts the selected wand as held, and also counts Paste Rotate and Paste Place as held while the session has a fixed selection or is in paste aiming. Undo also counts as held while build mode is active, regardless of flow. Neither paste control nor undo alone creates a session or enters build mode; Build Undo presses the existing UndoEdit use case for the last edit in any flow, without opening a menu. Its first block interaction is canceled and deferred through `system.run`; that route and `itemUse` share a per-player debounce using `BUILD_SPEC.pasteRepeatTicks`. Existing undo feedback appears on the action bar, including `nothingToUndo` without creating a session. Paste aiming and the clipboard remain after undo. Build mode enters after `BUILD_SPEC.modeEnterTicks` consecutive holding ticks and leaves after `BUILD_SPEC.modeLeaveTicks` consecutive nonholding ticks; returning to the current input resets the streak. A session is created only when the player first holds the wand. Active mode gates preview drawing, not the input handlers or edit jobs. It neither requires a bulldozer nor requests a camera, vehicle visibility, or HUD change. Bootstrap supplies `wantsChaseCamera: () => false` to vehicles and gives build a protection function combining `vehicles.isVehicleSpace` and `camp.isCampSpace`; leaving a vehicle has no build-mode effect.
- Agreement: Proposed
- Basis: [0198](../adr/0198-one-build-wand-without-a-bulldozer.md) Decision 2, "Holding the wand enters build mode after the existing grace delay; leaving it also has a grace delay. No bulldozer is required, whether on foot or riding."

### Press routing

- Applies to: Block interaction and item use with the wand, Paste Rotate, Paste Place or Build Undo, and attempted block breaking with the wand.
- Rule: The `routePress` decision table in `src/domain/build/flow/press.ts` maps the build flow, held role, event route, target and sneak state to one intent. On either route, Paste Rotate requests `rotateSelection` in `selected` and `rotateClipboard` in every other flow. Build Undo requests undo and Paste Place requests placement. These control intents are independent of target and sneak state. The control handlers cancel block interaction and defer the first event. Both routes share each control's debounce window. The existing use cases handle feedback when no session exists. A wand block tap can start a selection without a session. A wand air press without a session leaves it absent. The before-event block-break handler cancels every break with the wand held. The wand block-interaction handler also cancels the event. Outside paste aiming it accepts only `isFirstEvent` and defers work through `system.run`. The deferred callback rechecks the flow before selecting a point, confirming height, or opening the selection menu. In `baseHeight`, a wand air press or first block interaction samples the current gaze and fixes the height at either sneak state. The block interaction is canceled and confirmation opens no form. In `selected`, any block interaction with the wand opens the root shape menu, including interactions with doors and chests inside or outside the box. During paste aiming, the block event is canceled without a build action. The wand item-use handler uses separate per-player debounce windows. A sneak press in `pasteAim` uses `BUILD_SPEC.pasteRepeatTicks`; every other press uses `BUILD_SPEC.pressDebounceTicks`. A menu press cannot suppress the following commit, and two commit presses within the repeat window cannot paste twice even at different anchors. Every attempted press updates the last tick, including a rejected repeat, so a continuous held stream is suppressed until a sufficient gap. Outside paste aiming, item use ignores missing aim and leaves an aimed block to block interaction. With an air target, item use confirms height during the height step, opens the root shape menu during `selected`, opens utilities when idle or sneaking in other eligible flows, and otherwise requests a virtual endpoint. Both wand routes open the same selection menu at either sneak state. An idle session with no history and no confirmed box has an empty utility menu, so no form opens. In paste aiming it delegates to `PressPasteAim` even when the aim reader returns undefined: a plain press opens the menu, while only a sneak press with a block hit pastes. A sneak press with no target reports `pasteNoTarget` and preserves aiming. There is no left-click selection subscriber or gesture-duration detector; any accepted `itemUse`, including a device long press, follows this routing.
- Agreement: Proposed
- Basis: [0198](../adr/0198-one-build-wand-without-a-bulldozer.md) Decision 3, "Debounce a held press, which can repeat `itemUse` every 0.2 seconds, so it counts once."
- Basis: [0203](../adr/0203-build-wand-paste-aiming.md) Decision 3, "The wand retains its `itemUse` routing during paste aiming."
- Basis: [0229](../adr/0229-open-build-utilities-with-a-plain-air-press.md) Decision 1, "An air press in `idle` opens the utility menu without sneaking."
- Implementation: `routePress` in `src/domain/build/flow/press.ts` defines the decision table. The Bedrock handlers execute its intents and manage event cancellation, aim reads, deferral and debounce in `src/infrastructure/build/bedrock/handlers/wand.ts`, `src/infrastructure/build/bedrock/handlers/wandPress.ts` and `src/infrastructure/build/bedrock/handlers/pasteControls.ts`. The debounce implementation lives in `src/domain/build/pressDebounce.ts` and is wired in `src/infrastructure/build/install.ts`. Paste gestures share `src/application/build/pressPasteAim.ts`.
- Verification: `tests/domain/build/press.test.ts` checks the `routePress` decision table, every combination of press inputs and the flow-dependent Paste Rotate intent. `tests/infrastructure/build/pasteControls.test.ts` checks control dispatch, debounce and missing-session feedback. `tests/infrastructure/build/wand.test.ts` checks idle utility routing, before-event cancellation, deferred calls, virtual endpoints, repeat suppression, height routing, duplicate block and item events, and paste item-use routing. ### Point 1, material and lone-corner marker

- Applies to: The first valid block interaction from idle, then the `point1` flow.
- Rule: Point 1 stores the tapped cell, its dimension, and the block permutation's type and states as the sole build material. Starting a new point clears the old confirmed box. Unreadable cells, air, fluids, the generic shulker-box ID, and data-holding kept types are refused as material. Terrain is otherwise eligible. Later endpoints preserve this material. Point selection reports `pointSet`; material naming occurs when choosing a roof/solid or starting a shape edit. The lone marker is the unit cube boundary's eight corners plus twelve edge midpoints, twenty distinct points, using `minecraft:endrod` through the owning player's `spawnParticle`. Preview redraws occur on `BUILD_SPEC.outlineInterval`; the marker appears on alternate redraws. Only the flow's dimension is eligible. Setting the endpoint removes the lone marker, while a separate end-block cube may still use endrod. One point alone cannot build or copy a confirmed selection.

### End-point aiming and virtual point

- Applies to: A selection with point 1 and no fixed endpoint.
- Rule: `BedrockAimReader` reads the head location, view direction, and optional block hit using `maxDistance: BUILD_SPEC.reach`; failures return no aim. A block hit supplies the live endpoint. Otherwise `virtualEndPoint` intersects a vertical plane through the first block's center, normal to the dominant horizontal look axis, with x winning a tie. It floors the coordinates and fixes the normal-axis coordinate to point 1. A nearly parallel ray, intersection behind the origin, or intersection beyond `BUILD_SPEC.reach` gives no virtual point. Preview draws the inclusive bounding-box edges at block centers, thinned by `BUILD_SPEC.outlineMaxPoints`, and the endpoint's unit cube. A second accepted block interaction or an air press with a valid virtual point fixes the base. A line goes directly to `selected`. A rectangle or box enters `baseHeight`, keeping the horizontal extent and lower layer of the two points. The upper layer starts at the higher point within the live height caps. The ordinary selection outline redraws every `BUILD_SPEC.outlineInterval` as the player raises or lowers their gaze. The next wand press samples the current gaze and confirms the height without opening a menu. In `selected`, the `Selection` stores the dimension, inclusive box, and material, and the flow keeps the two tapped points next to it. Confirming the live height, Rotate, Place, Fill, Frame, and Remove above or Fill below change or keep the box but never the tapped points, and an Undo that restores the box keeps them too; only a roof or solid build replaces them with the minimum and maximum corners of its new box. Its outline stays fixed until the selection changes, and the endpoint marker stays on the tapped end point, even after Rotate turns the box. A subsequent wand press opens the menu. The selection persists while the wand, Paste Rotate, Paste Place, or Build Undo is held. An unrelated item clears it after `BUILD_SPEC.modeLeaveTicks`. Fixing the base or a line before the enter delay expires activates build mode so the same leave delay applies.
- Agreement: Proposed
- Basis: [0198](../adr/0198-one-build-wand-without-a-bulldozer.md) Decision 5, "Aimed blocks give the end point; aiming at air gives a virtual point on the vertical plane through point 1 facing the player, snapped to the dominant horizontal look axis."
- Basis: [0253](../adr/0253-persistent-build-selection-and-tool-swapping.md) Decision 1, live selection height and explicit menu opening.

### Shape derivation and shape menus

- Applies to: A fixed pair of endpoints in `selected` flow.
- Rule: Classify the fixed selection by the axes on which its minimum and maximum differ. One gives a line, two give a rectangle, and zero or three give a box. Bounds are inclusive. The root ActionForm uses `form.shape_title` and offers Adjust height, Cut, Remove above, Build shape, Copy, Fill below, Cancel in that order. Adjust height is hidden for lines. It returns rectangles and boxes to live height with a one-layer base at the selection bottom and the current height clamped to the selection height limit; the next press confirms the new height and retains the selection. Dismissing the menu preserves the old height. Build shape uses `form.build_shape`. The build ActionForm uses `form.build_shape_title` (Shape), and its final Back button uses `form.back`. One per-player exclusive lock spans root/build navigation and all follow-on terrain, height and contents forms. Back or dismissal of the build form closes the build level and reopens the root in a loop under the same lock; Root dismissal preserves the selection and outline. Root Cancel clears the selection and returns to idle. A form response applies only if its selection and menu level are still current and the action is still offered. A line replaces Build shape with Place and has no submenu. Build shape opens a submenu: vertical rectangles offer Fill, Frame; horizontal rectangles offer Fill, Frame, Gable roof, Hip roof, Cylinder, Sideways cylinder, Sphere, Cube; boxes offer Fill, Faces only, Walls only, Gable roof, Hip roof, Cylinder, Sideways cylinder, Sphere, Cube. Each build submenu ends with Back. The selected flow stores `menuLevel` (`root` or `build`), initialized to `root` when a line or live height is fixed. `shapeMenu` offers only root entries, `buildMenu` only build entries, and `isShapeEntryOffered` checks the current level. `openBuildMenu` and `closeBuildMenu` change only that level; Back preserves points, dimension, material and preview, and a new wand press opens the root even if a refused action had left the build level active. `OpenSelectionMenu` returns the root menu entries for the current selection. `OpenBuildMenu` and `CloseBuildMenu` update the existing session and refresh its preview; `DescribeBuild` exposes the level only in `selected`. Frame keeps the rectangle perimeter; Faces only keeps all box boundary faces; Walls only keeps horizontal perimeter columns without floor/ceiling interiors. Thin dimensions with no interior reduce to fill. Replace has no flow, menu entry, use case, or form label. Contents and terrain Cancel return to point-1 aiming with the original first point and material. Place, Fill, Frame, Faces only and Walls only keep the original box selected at the root and available for Copy. Roofs and solids retain a root selection of the minimal Fill bounds and confirm the same box for Copy. Cut confirms the box too, but enters paste aiming. The rotation core turns the entire selected box clockwise by one quarter turn and replaces its box while retaining dimension and material; Paste Rotate applies the turn immediately and keeps the rotated box selected. An existing confirmed box in that dimension also becomes the rotated box. For source size (sx, sy, sz), `planRotationAboutCenter` sets `target.min.x = source.min.x + trunc((sx - sz) / 2)` and `target.min.z = source.min.z + trunc((sz - sx) / 2)`, with target size (sz, sy, sx) and Y unchanged. The half-cell offset rounds toward zero and negative zero is normalized. Swapping the sizes makes consecutive offsets exact negatives, so two turns, and therefore four, return the original box exactly. Refusal preserves the selection. ### Roofs

- Applies to: Gable roof or Hip roof chosen on a horizontal rectangle or box.
- Rule: Roof height grows upward from the selection's lowest layer and ignores the selected height. Gable layers narrow across the shorter axis, leaving the ridge along the longer axis. Ties run along x. Hip layers narrow on both axes. An even square retains a symmetric two-by-two top at full inset.
  Stair material has numeric `weirdo_direction` and boolean `upside_down_bit` states. It sets a fixed 45-degree pitch using `floor((shortSpan - 1) / 2) + 1` layers, with each layer inset by one cell along each sloped axis. Each stair descends toward the nearest eave on a sloped axis, resolving ties in west, east, north, south order. A layer one cell wide along a sloped axis uses upside-down stairs with the material's original direction to make a flat ridge. Fill orients every cell. Hollow leaves the bottom open and retains the eave perimeter, gable end walls, and full top layer. A single-layer roof stays whole.

Live aiming chooses the layer containing the point on the footprint's vertical center line nearest the forward view ray. Nearly vertical rays use the stored `previous` height. Preview computes a height without storing it and confirmation stores the aimed height. The contents menu opens after height confirmation. Fill places all layers and Hollow keeps cells with an exposed face, including the bottom and top.

### Copy

- Applies to: Shape-menu Copy and Cut, plus selection-utility Copy of a confirmed box.
- Rule: Copy and Cut record the player's cardinal facing when chosen in the menu and immediately capture the inclusive selected box. Utility Copy reads facing when chosen for the confirmed box. ### Edit protections and limits

- Applies to: Shape, roof, solid, Cut, Remove above, Fill below, paste, selected-box rotation, and undo in every game mode.
- Rule: Before writing each planned cell, `EditJobs` reads its current permutation and skips unreadable cells, kept types, cells denied by `mayEdit`, and unchanged states. `mayEdit` denies bootstrap-protected vehicle/camp space, laid-tagged blocks, unavailable blocks, and engine read failures. Build kept types are `PLACE_KEPT_BLOCKS` plus `BUILD_KEPT_BLOCKS` (sign variants, spawners, vault, command-block variants, structure block and jigsaw); air and fluids are writable. Kept types protect only cell jobs (shapes, roofs, solids, Remove above, Fill below and cell Undo). Paste preflights every cell of its entire target box with `mayEdit`; one failure refuses the whole paste as `pasteBlocked`. Containers and other kept types do not protect a paste. Paste refuses a busy session, captures a Memory undo snapshot of the target box (a refusal reports `pasteFailed`), removes non-player entities there except this addon's vehicles, and places the clipboard structure at the anchor. If placement fails, it removes entities again, places the snapshot back, discards it, reports `pasteFailed`, and keeps earlier history. Paste runs synchronously without `EditJobs`; on success it records the snapshot, reports the box volume, and moves the owner out of solid cells with the shared escape behavior. Shape and heighted edits limit the actual style's planned cell count to `BUILD_SPEC.maxVolume`; a large hollow bounding box can therefore be accepted. Cut limits the entire bounding volume to `BUILD_SPEC.maxCopyVolume`, refuses busy sessions, and preflights every cell with `mayEdit`; any denial refuses the whole cut with `pasteBlocked`. Containers and other kept types do not protect a cut. Both clipboard and snapshot captures must succeed before any removal; refusals preserve flow, confirmed box, clipboard and history and discard newly captured handles. Before changing session state, Cut removes non-player entities and clears every block to air without drops, including containers, signs and fluids; this addon's vehicles are neither copied nor removed. External fluids may flow back afterward. Cut runs synchronously without `EditJobs`. After clearing succeeds, it replaces the clipboard and records one snapshot, discarding the previous structure clipboard and any snapshot handles evicted by the shared history cap, and reports the full volume. If clearing fails, it places the snapshot at the source minimum to restore blocks and removed entities. Successful rollback discards both new handles, leaves clipboard, history, selection and flow unchanged, logs a warning, reports `cutRestored`, and returns false. If rollback also fails, Cut retains the snapshot in history, replaces the clipboard and enters paste aiming, logs a warning, reports `cutIncomplete` without an undo hint, and returns true so Undo can restore the area. Snapshot Undo restores the whole source box, including contents and eligible entities; it does not restore the previous clipboard. Selected-box rotation first limits the union of the source and target boxes to `BUILD_SPEC.maxCopyVolume`, then refuses a busy session, then checks `mayEdit` on every union cell; a denial reports `rotateBlocked` without changing anything. Target cells outside the source are overwritten, including terrain, water and neighboring blocks. It captures the union snapshot before the source structure; either capture refusal reports `rotateTooLarge` and discards new handles. It clears eligible entities and all blocks in the source, then places the source at the rotated target minimum with turn 1. Failed clearing or placement attempts restoration by clearing eligible union entities and placing the snapshot at the union minimum, discards both handles, logs a warning and reports `rotateFailed`, preserving selection and earlier history. Success records the union snapshot, discards the source handle, updates the selection, moves the owner out of solid target cells with the shared escape behavior, and reports `rotateDone` with the source volume. Excluded `yasu_ride:` and `yasu_build:` entities stay where they are. Undo restores the whole union, including cells the target grew into. Rotation adds to the same capped history as paste, cut and cell edits; only evicted snapshot handles are discarded. Cell jobs share `BUILD_SPEC.blocksPerTick` planned-cell budget, round robin, and do not read game mode or consume/return inventory. Failed writes are skipped, not rolled back. Protections are rechecked as the job runs.

### Continuous paste and undo

- Applies to: Per-player edit scheduling, repeat suppression and history.
- Rule: Each session allows one running edit; another edit reports busy and is not queued. `PasteAt` first ignores the same anchor and turn within `BUILD_SPEC.pasteRepeatTicks`, then checks protection, then busy state. A refused paste never records a repeat window. A successful paste records the anchor/turn/tick. Successful paste, cut and rotation operations record snapshot entries in the same per-player history as cell edits. Rotation snapshots and shape-build cell records carry the pre-edit box in the optional `selectionBefore` field. When Undo restores a snapshot or starts a cell undo, `UndoEdit` reports that box as `restoredSelection`. Snapshot Undo restores the pre-turn selection in the selected flow in the recorded dimension. All shape builds record their resulting bounds in `selectionAfter`. When those confirmed bounds are still selected, cell Undo restores both the active and confirmed box to the pre-build bounds. All kinds share one cap of `BUILD_SPEC.undoDepth` (10) entries. Adding an entry beyond the cap evicts the oldest entry first; if it is a snapshot, its structure handle is discarded. Each completed nonempty undoable cell job (shape, roof, solid) records only successfully changed cells, including exact before/after permutations and dimension. Empty cell jobs add no history; a paste or cut records a snapshot even for an all-air box. A job is dequeued before its history is committed and feedback is shown. A feedback failure is logged and does not repeat the commit. A job that throws is dropped; its already applied changes are committed to history and the session is released from busy. Other jobs keep running. For a cell entry, Undo removes the newest record and plans its before states in reverse order in the recorded dimension, with each recorded after state as its expected state. It compares the current state with the recorded after state before the unchanged-state check. The expected-state comparison ignores `minecraft:corner` because Bedrock recomputes stair corners from neighboring blocks. The block type and all other states must match. Already-reverted cells equal to before are left alone without being counted as skipped. Cells that fail the expected-state comparison and differ from the exact before state are conflicts and remain unchanged. Conflicts and cells that are protected, unreadable/unloaded, kept types, or fail to write are counted as skipped. Cell Undo shows `undoDone` when none were skipped, otherwise `undoDonePartial` with restored and skipped counts; it adds no redo record. An unrestored cell is given up: the record is consumed when Undo starts, and no retry record is kept (accepted limitation, `src/application/build/undoEdit.ts`). Build Undo uses the same history as the menu and works in any flow; without history it reports "There is nothing to undo." without creating a session. Cell undo retains clipboard and paste aiming and clears the same-anchor-and-turn repeat window. Ending paste or switching items leaves an already running job able to finish and record history while the session exists. Completed undoable edits show the action bar message "Changed %s blocks. Long-press the air to undo." only when `airPressOffersUndo` holds for the session flow at the moment the job finishes (idle, where a plain air press opens the utility menu offering Undo); a job that finishes outside idle shows the count-only message "Changed %s blocks." instead. The first nonempty undoable edit in each session that finishes in such a state also sends the chat line "Made a mistake? Long-press the air with the wand and choose Undo." Empty edits, undo, and edits that finish where the gesture is not true never consume or show the chat hint. The hint resets when the session is removed on disconnect or reload. Each successful Paste Rotate turn of a selected box records a snapshot. Each Undo restores one turn, including overwritten neighbors. Undo takes the newest entry of either kind. Snapshot undo first checks `mayRestore` for every cell of its recorded box (space protection only; laid-tagged blocks do not block it, because a structure paste may have placed them). Any space-protected cell reports `pasteBlocked` and puts the entry back unchanged for retry, without calling the structure store. Otherwise it calls `clearEntities`, places the saved structure at the box minimum, and discards its handle. Successful restoration includes containers and eligible entities, clears the last paste marker, and reports `undoDone` with the box volume, retaining the clipboard and paste aiming. If placement returns false, it still discards the handle, drops the entry, logs one warning, reports `undoFailed`, and leaves the flow unchanged.

### Session lifetime

- Applies to: Selection flow, confirmed box, clipboard, history, debounce and queued jobs.
- Rule: `InMemorySessionRepository` keeps one session per player ID; reload loses all state. Death and dimension change invoke End pasting in every flow, clearing selection, clipboard and confirmed box while retaining history and the session. ### Automatic escape after an edit

- Applies to: Every successfully completed edit job, including shapes, solids, Paste, Undo, and irreversible edits.
- Rule: Each job run reads its initiating player's occupancy once, retaining feet and head cells only in the job's dimension. A successful write to either cell marks the job as having touched its owner; skipped, unchanged, conflicting and failed writes do not. At normal completion, a marked job rechecks occupancy and moves only its owner if a readable current feet or head cell is neither air nor water nor lava (including flowing fluids). ### Fill below

- Applies to: Every selection shape, through Fill below, placed after the shape entries and before Copy.
- Rule: Use the selected x/z extents, each at most `BUILD_SPEC.maxTerrainSide` (32), and the higher of the two points the player originally tapped as the inclusive top. The top does not follow the live height, Rotate, Place, Fill, Frame, or an earlier Remove above or Fill below on the same selection, so repeating Fill below on a selection whose live height was raised above both points fills to the same top again. For an oversized footprint, report the bounding prism count from the world floor through that original top layer. Refuse listed falling or support-dependent materials at menu choice with `fillMaterialRefused`, preserving the endpoint flow. Confirm the operation, footprint, bottom and top height, warning that it cannot be undone; cancellation returns to aiming from the originally tapped first point. The displayed bottom is the inclusive minimum of the player's dimension, read in infrastructure as `dimension.heightRange.min`. The domain planning bound remains `BUILD_SPEC.worldBottomY`; unreadable cells below the dimension floor are barriers. Seed every fillable top-layer cell and follow six-neighbor paths, including upward paths behind overhangs, down to `BUILD_SPEC.worldBottomY` (-64). Air and liquids are fillable; unreadable cells, solids and `mayEdit` refusals are barriers. Never write outside the selected x/z bounds or above the top; disconnected cavities stay untouched. Each planning read occurs at most once, with a `SCAN_STEP` consuming one job-budget step; each proposed write consumes another. A `Uint8Array` stores visited marks before reads, and a numeric index stack holds pending cells. The maximum prism has 393,216 marks and at most 786,432 read/write steps, approximately ten seconds at 4,096 steps per tick and 20 ticks per second. The job keeps the original box selected and available for Copy, uses no history and count-only completion, preserves earlier Undo history, and uses the shared owner escape behavior. Selecting a slope can leave a cliff at the boundary; a player in an outside side passage may be trapped and is not moved because their cells were not written.
- Agreement: Accepted
