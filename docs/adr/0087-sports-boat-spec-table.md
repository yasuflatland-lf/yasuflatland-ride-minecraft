# 0087. Keep the sports boat tuning in one spec table

- Status: Superseded in part by 0089 (the boat's handbrakeGrip)
- Date: 2026-10-20
- Supersedes in part: 0055 (the boat keeping its tuning in its profile and drive)

## Context

0002 asks that each tuning value lives in one place. 0055 put the SUV's tuning in `SUV_SPEC` (`kinds/suv/spec.ts`) but let the sports boat (0051) keep its profile and motion limits in `kinds/sportsboat/profile.ts` and its water drag and height in `drive.ts`. After that, 0059 added the trim and roll values in `attitude.ts`, 0061 raised the roll values there, 0085 halved the trim values there, and 0063 added the deck draft and margin in `deck.ts`, so the boat's tuning sits in four files. The camper (0067) followed the SUV with `CAMPER_SPEC`, which leaves the boat as the only kind without a spec table. Three of the boat's tables (`SPORTSBOAT_DRAG`, `SPORTSBOAT_WATER`, `SPORTSBOAT_ATTITUDE`) were not frozen.

## Decision

- `SPORTSBOAT_SPEC` in `src/domain/vehicle/kinds/sportsboat/spec.ts` holds every sports boat tuning value: driving limits (`maxSpeed`, `maxReverse`, `accel`, `reverseAccel`, `brake`, `drag`, `turnRate`, `steerFullSpeed`, `grip`, `handbrakeGrip`, `creepSpeed`), body (`height`, `ramFront`, `ramHalfWidth`), water drag estimate (`waterDragInitial`, `waterDragMin`, `waterDragMax`, `waterDragSmoothing`, `waterDragMinGiven`), attitude (`maxTrim`, `trimRiseRate`, `trimSettleRate`, `maxRoll`, `rollRate`) and deck (`deckDraft`, `deckMargin`). It is frozen and imports nothing
- `SPORTSBOAT_MOTION`, `SPORTSBOAT_PROFILE.ram`, `SPORTSBOAT_DRAG`, `SPORTSBOAT_WATER`, `SPORTSBOAT_ATTITUDE`, the drive's collision box height, `DECK_DRAFT`, `DECK.margin` and the `trim`/`roll` property ranges in the entity contract read their values from `SPORTSBOAT_SPEC`, and each derived object is frozen
- The water medium `SPORTSBOAT_WATER` stays in `drive.ts`, next to the drag estimator that overrides its drag every tick. The SUV and camper keep their media in their spec files; the boat's spec stays free of imports instead, so it needs no `Medium` type
- Not tuning, so it stays where it is: the seat positions, headlight beams and placement rule in `SPORTSBOAT_PROFILE` (they mirror the Behavior Pack and are checked against it), and the deck geometry parts in `deck.ts` (generated by `tools/gen_sportsboat.py`)
- The values do not change

## Consequences

- Every kind now has `kinds/<kind>/spec.ts`, so AGENTS.md lists `SUV_SPEC`, `CAMPER_SPEC` and `SPORTSBOAT_SPEC` without an exception
- Tuning the boat means editing one table
- The derived names (`SPORTSBOAT_MOTION`, `SPORTSBOAT_DRAG`, and so on) stay so that the drive, the tests and the test pack keep their imports; a later kind should start from a spec table instead of growing a profile
- Revisit if a value needs to differ per boat instance rather than per kind
