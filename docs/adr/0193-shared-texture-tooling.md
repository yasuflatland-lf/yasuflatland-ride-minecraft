# 0193. Share texture tooling between generators

- Status: Proposed
- Acceptance condition: owner decision pending (see #1193)
- Date: 2026-10-30
- Supersedes in part: [0057](0057-skip-model-check-when-inputs-unchanged.md): the model CI path filter that left out tools/gen_model.py and tools/gen_sportsboat.py
- Supersedes in part: [0147](0147-light-the-lamps-with-a-pbr-emissive-layer.md): the rationale for copying texture tooling into each generator

## Context

The generators copy the same texture tooling, and the copies have started to drift (#977):

- the MER triples `MER_LIT = (0, 255, 255)` and `MER_OFF = (0, 0, 255)` are copied into the SUV, camper, sports boat and bulldozer generators, while `tools/mer_atlas.py` keeps its MER values as palette pairs;
- the texture set JSON is built in five places;
- `lit_textures(kind, width, height, pixel)` exists four times, and the copies differ only in how they test whether a texel is lit;
- the camper, sports boat and bulldozer each carry an `emit`/`png` writer with a `--check` mode, and `mer_atlas.write_or_check` is a fourth variant that stops at the first stale file and compresses at zlib level 9.

0147 justified the copies because isolated Python execution (`python3 -I`) prevented importing a shared helper. `tool_loader.load_tool` has since removed that obstacle. The SUV is about to gain per-paint MER maps and a lit texture over several regions, which would add another copy.

## Decision

Generators load shared modules with `tool_loader.load_tool`:

1. `tools/mer.py`: a validated `Mer(metalness, emissive, roughness)` value with `rgba()`, the constants `MER_OFF` and `MER_LIT`, `mer_painter(lookup, default)`, and `layout_mask(layout, region_name, local_mask)` for bounded local-to-atlas masks. It does no I/O.
2. `tools/texture_io.py`: the sole generated-asset writer for every entry in `tools/generators.json`, including the creative item catalog and preview renderer. `Outputs(check)` writes JSON and PNG files, or under `--check` compares JSON parsed and PNGs by decoded pixel rows, collects every stale path, and reports them in `finish`, appending the exception reason in parentheses when reading or decoding fails. `Outputs.json(path, doc)` accepts a document, not pre-serialized text, and always writes `json.dumps(doc, separators=(",", ":"), ensure_ascii=False) + "\n"` as UTF-8, without caller formatting parameters. `Outputs.fixture_json(path, doc)` writes the generated `tests/packs/fixtures/camper-areas.json` with `indent=2` and a trailing newline; both methods compare parsed JSON in check mode. `png` accepts RGB or RGBA texels and pads RGB texels with alpha 255 once before writing or comparing. `png` takes a `compress_level` so each generator keeps its PNG bytes (`mer_atlas` uses 9, the others the zlib default). `rgba` accepts the renderer's packed RGBA pixels and preserves its compression level 9 and RGB pack icons. `Outputs.touched` records every written or checked `Path`, including stale or missing files; the runner's `--report-touched FILE` collects these as JSON Lines with generator ids and repository-relative paths, including secondary writers such as monitors. `texture_set_doc` and `write_texture_set` build the 1.16.100 texture set.
3. `tools/lit_textures.py`: `build_lit_textures` writes `<kind>_lit.png`, `<kind>_lit_mer.png` and `<kind>_lit.texture_set.json` from a colour callback and an `is_lit` test. `build_layout_lit_textures` takes a `Layout` and a named region-local mask, deriving companion dimensions and relocating the mask before delegating to that writer.
4. `tools/geometry_passes.py`: `PassSpec(identifier, keeps_face)`, `select_faces` and `partition_geometry` split a built geometry into render-pass geometries. Every output keeps every bone with its `name`, `parent`, `pivot`, `rotation`, `mirror` and `locators`, so animations and part visibility still bind; a cube appears only when a face is kept, and its `uv` holds only the kept faces, deep-copied. `partition_geometry` raises `ValueError` naming the bone, cube index and face when a face is kept by no spec or by more than one; `select_faces` raises when it keeps no face. It does no I/O.
5. `tools/texture_variants.py`: `write_variants` stores each distinct colour and MER content once for a list of paint `Variant`s and returns a `VariantTextures` (`color_of`, `mer_of`, `stored()`). A stored colour is identified by the pair of colour and MER bytes, because the client resolves a texture set by the colour path. The first variant of each pair keeps its name, and later equal variants map to it with no files written. MER files are deduplicated by MER bytes alone: one `<kind>_mer.png` when every variant shares a MER, otherwise `<name>_mer.png` for the first variant of each distinct MER. It writes one texture set per stored colour that has a MER, and none for a kind without a MER, through `texture_io.write_texture_set` and every file through `Outputs`, so `--check` covers it.
6. `tools/region_atlas.py`: kind-neutral frozen `Region`, `Placement` and `UvRect` values, `RegionFace`, `RegionRef`, `RegionRegistry`, `Layout`, `pack`, `render_atlas`, and `audit`. Regions accept any Enum member as their material. The deterministic packer preserves its existing algorithm and returns unflipped placements. `Layout.placement(name)` returns a placement; `origin(name)` retains the plain-origin interface and raises `ValueError` for flipped placements. `UvRect.of(face)` reads region-local UVs, `to_atlas` maps them through a placement, and `apply(face)` writes UVs and signed sizes without numeric coercion. The sole mirroring rule lives in `UvRect.to_atlas`: on x, a flipped placement maps `u` to `x + (W - u)` and `w` to `-w`; otherwise it maps `u` to `x + u` and preserves `w`. The same rule applies on y with `H`, including already negative sizes. Point resolution, face containment, rendering and audits use this mapping; rendering and pixel audits precompute column and row indices per region. Audits retain region-local mismatch coordinates and validate both endpoints of live bound faces.

The camper modules and `tools/scooter_atlas.py` load `region_atlas` directly through `tool_loader`. `tools/camper_regions.py` is the camper wrapper: it retains only its `Material` enum, curtain constants, width function and pixels, with no re-exports of shared atlas names. Material classifications are `SWATCHES_MIXED`, `METAL`, `LACQUER`, `GLASS_COAT`, `VINYL`, `WOOD`, `FABRIC`, `CARPET`, `TILE`, `STONE`, and `DARK_LACQUER`. They identify finishes for companion-map tooling; they do not assign a uniform MER value to the mixed base. The camper retains the shared `swatch_atlas.Atlas` for nested swatches and hardware (0190). Scooter faces resolve through `UvRect` and copied placements; packing produces no flips yet. This extraction preserves every generated geometry, texture and preview byte.

`tools/camper_mer.py` builds packed RGBA bytes from `Layout` materials, with alpha 255 and G = 0 everywhere. `MER_BY_MATERIAL` assigns `(metalness, 0, roughness)`: METAL `(255,0,60)`, LACQUER `(0,0,80)`, GLASS_COAT `(0,0,65)`, VINYL `(0,0,180)`, WOOD `(0,0,150)`, FABRIC `(0,0,245)`, CARPET `(0,0,250)`, TILE `(0,0,80)`, STONE and DARK_LACQUER `(0,0,85)`. `SWATCHES_MIXED` uses nested semantic tables instead of a uniform value. Steel/chrome/slat/aluminium use metalness 255 and roughness 75/50/80/80; white/panel/ivory use dielectric roughness 85/90/80; dash/dark_dash/dash_pad use 185/190/175; gauge/needle use 65; wood/wall_in use 155/160; tweed/tweed_line/curtain use 245, piping 235, carpet_beige 250; khaki/stripe/tan use 100. Ribs use dielectric roughness 85, door/vent/bolt hardware metalness 255 and roughness 75, and mirror chrome retains `(255,0,26)`. Unclassified swatches and unused space default to `(0,0,255)`, including lens, marker, dome and glow swatches. Shared swatches apply the same finish wherever sampled, including exterior surfaces. Diffuse colour, alpha and baked highlights do not determine the MER values.

`tools/camper_golden.py compare --golden-dir DIR [--area NAME]` compares current pack geometry cube counts per bone and registry sizes/origins with `final-model.json.gz` and `final-regions.json` in the supplied directory. Golden `packed_origin` takes precedence over its source `origin`; the spike's descriptive base name is normalized to `base`. Area selection uses exact labels in current area ranges and golden cube `_area` tags, restricting regions to those used by that area. Current module labels and spike visual-feature labels can differ; a label missing on either side is reported as a difference, rather than guessed from overlapping feature groups. Current counts inspect actual cubes within the ownership ranges, so a stale range cannot count deleted geometry. A unified diff exits 1 on mismatch; a match exits 0. Golden artifacts stay outside the repository and their path is never embedded in tooling. Small temporary fixtures test the CLI; the unfinished camper is expected to differ from the completed-series golden.

The copies are no longer justified, which amends the rationale in 0147. Adopting compact JSON changes whitespace and file sizes but preserves parsed content; PNG bytes remain unchanged. The camper, SUV, sports boat, bulldozer, camping gear, and MER atlas users (fire pit, Dutch oven, Gas Lantern) use the shared modules.

`tools/generators.json` is the authoritative plan for every generator's `outputs` and `reads` outside `tools/`. Each entry has an optional `id`, defaulting to its `script`; ids must be unique, while entries may share a script. Dependencies, output ownership reports, and `--report-touched` identify entries by id. All files under `tools/**` are implicit inputs; paths containing `__pycache__` are excluded by input consumers. `tools/generated_outputs.py` exposes the frozen `GeneratedOutput(generator, pattern, tracked)` value and `OutputManifest.load`, `outputs`, `matches`, `inputs`, and `untracked_patterns`. Patterns use POSIX repository-relative `fnmatch` semantics, with stars matching across folders. Output patterns cover only generated files and have exactly one owner per file. The preview renderer's outputs, including rendered item icons, use `tracked: true` so they remain committed when other generated files become build outputs.

The preview renderer has six entries, `render_preview.py:<scene>` for `suv`, `boat`, `camper`, `bulldozer`, `scooter`, and `gear`, each with `--scene <scene>`, scene-specific reads, and the shared `after` list. SUV owns its previews and all three pack icons; gear owns its previews and rendered item icons; each other scene owns its vehicle previews. All six retain the pack manifest validation reads from `--icons`. The scooter reads add `scooter_white.png` and `scooter_lit.png`, which the builder uses but the former combined entry omitted; `scooter.png` remains declared to preserve the old input coverage.

`--only ID [ID ...]` selects entries in manifest order, deduplicates ids, and verifies ownership for exactly those entries in write or `--check` mode. It bypasses `after` dependencies and the after-generators barrier, so callers must run `pnpm generate` first. Unknown ids fail with the valid ids listed. It rejects `--ensure`, `--status`, and listing flags, and never invalidates or writes the generation stamp.

`tools/run_generators.py --list-outputs [--untracked]` and `--list-inputs` expose the plan without running generators. The runner performs no Biome step and the plan has no `format` key. `afterGenerators: true` runs the six `render_preview.py` entries after every other generator in write and check modes. Biome uses Git ignores to skip generated build outputs; hand-written JSON stays under normal formatting. The SUV animation retains two-space indentation through `Outputs.fixture_json`; the complete item atlas uses compact JSON generated from `tools/item_texture_base.json` and the gear spec. The model CI job consumes manifest inputs and committed outputs, excluding untracked outputs, retaining package, tool-version, and workflow triggers. This amends 0057's former exclusion of generator scripts. The generated section of `.gitignore` lists exactly `--list-outputs --untracked` in plan order. `tests/tools/generatedOutputs.test.ts` enforces equality, complete touched-output ownership, retained pattern matches, no tracked build outputs, and exclusion of hand-written pack models and textures. Generated outputs need no Linguist attributes or Biome exclusions (0248).

`pnpm generate` invokes `python3 -I tools/run_generators.py --ensure`. It hashes the sorted paths and contents matched by `OutputManifest.inputs()`, excluding `__pycache__`, together with `sys.version`. The ignored `.cache/generated/stamp.json` records the SHA-256 fingerprint and concrete build-output paths. An unchanged fingerprint with every recorded output present skips generation. A missing or invalid stamp, changed input, or missing output regenerates the build assets. The stamp is invalidated before writes and replaced atomically only after all generators succeed, using the post-generation fingerprint because some manifest inputs are generated assets. Generator failures identify the entry by id and preserve its exit code.

Independent generators run concurrently through `concurrent.futures.ProcessPoolExecutor`, one process per generator. Entries declare real ordering through `after: [id, ...]`; unknown dependencies and cycles fail. The item catalog reads source specs, so it needs no dependency on camping gear generation. The renderer declares all asset producers in `after` and retains its after-generators barrier. `--ensure` skips entries marked `afterGenerators: true`. Outputs from those entries are excluded from build-output freshness checks and the stamp; their outputs under `packs/` are checked separately as retained outputs. This selection depends on `afterGenerators`, not the script file name. `pnpm model` forces generation and rendering; `pnpm model:check` ensures fresh packs, then checks every generator's output, including the committed renderer outputs, and output ownership through `run_generators.py --check`. The SUV animation uses `tools/templates/suv.anim.json` and the item atlas uses `tools/item_texture_base.json`, so deleting generated pack files cannot delete the source needed to recreate them. Generated pack contents remain unchanged, but untracked outputs are ignored build artifacts (0248).

Build invokes the Python ensure command before esbuild. Vitest invokes it once per run through `tests/support/generatedSetup.ts`, before collecting pack or tool tests. The dev server and in-game driver use `scripts/generated-files.mjs` to build when the production or test bundle is missing, source or build configuration is newer, or generated assets are stale or missing. The runner's read-only `--status` returns JSON freshness and missing-output information for these callers. Packaging rejects missing generated assets, including committed rendered item textures and pack icons, with an instruction to run `pnpm build` first. Missing renderer outputs do not force rendering through `--ensure`; they must be restored or regenerated with `pnpm model`.

## Consequences

- A fix to writing or checking lands once for every generator in the plan; lit-texture fixes are shared by their adopters.
- A shared-module change can affect several generators at once. `pnpm model:check` runs the generator runner in check mode, including vehicles, gear, models, textures and previews, so drift in any adopter's output fails it.
- Generated pack JSON occupies one line per file and is not expanded by Biome; the formatted ownership fixture remains readable.
- Adding or changing an output or external read requires updating its generator entry and the matching Biome exclusions for JSON outputs. Manifest coverage and attribute tests catch output-list drift.
- The model job also runs for tools that do not feed the renderer, such as `tools/gen_sounds.py`. That costs CI time on those pull requests, which are rare.
