# 0198. One Build Wand without a bulldozer

- Status: Proposed
- Acceptance condition: the Build Wand series is finished and its touch verification passes (#1038)
- Date: 2026-10-31
- Supersedes in part: [0178](0178-bulldozer-build-tools-in-a-separate-namespace.md): the bulldozer requirement in Decisions 3 and 4, the two items in Decisions 3, 8, and 13, the third-person build camera in Decision 5, the bulldozer-relative paste offset and moving preview in Decision 7, the hit and use mapping in Decision 8, and the Build Tool form in Decision 11
- Extends: [0137](0137-clear-block-columns-with-the-blade.md): the kept block list
- Extends: [0183](0183-mark-a-lone-selection-corner.md): the first-point marker

## Context

The build tools of 0178 require a bulldozer and two items, leaving the player to switch among them and the building material. An iPad test in Creative while riding the bulldozer showed that a block tap fires `playerInteractWithBlock`, while a long press repeats `itemUse` and does not fire a block hit. The selected block follows the head view ray rather than the finger, and the third-person build camera obscures that target. The existing hit-to-pos1 mapping therefore cannot work on touch.

The owner wants one item for the whole build, usable on foot or on a bulldozer, on touch and PC, in Creative and Survival. The design is recorded in the Build Wand spec.

## Decision

1. Keep `yasu_build:selection_wand` as the Build Wand and give it the Build Tool's icon. Remove `yasu_build:build_tool`, its recipe, creative catalog entry, and lang keys. Remove Replace. The other Building Tools items are unchanged. Players holding the removed item lose it.
2. Holding the wand enters build mode after the existing grace delay. Fixing the base or a line before that delay ends activates build mode so the selection has the full leave grace period. Holding Build Undo keeps an active build mode alive in any flow. Only the wand creates a session. No bulldozer is required, whether on foot or riding. Build mode draws outlines and previews but does not change the camera, hide a vehicle, or show a HUD.
3. A block tap or right-click uses `playerInteractWithBlock`. A PC right-click in air or a touch long press can emit `itemUse`. A short touch tap on empty air emits no event. [0257](0257-tap-the-build-wand-virtual-block-through-an-invisible-target-entity.md) defines a touch target for short taps. Debounce a held press, which can repeat `itemUse` every 0.2 seconds, so it counts once. In live base height aiming and with a fixed selection (`baseHeight` and `selected`), route `itemUse` regardless of the head view ray's target. Reserve the shared press debounce window in the block before event for these actions so a paired `itemUse` counts as the same press. In other flows, apply the existing flow and target rules to each accepted `itemUse`, including the paste aiming rules in ADR 0203. The wand does not infer gesture duration from the event. Cancel block breaks while the wand is held. Ordinary left-click does not select a point.
4. The first block tapped is point 1 and its block type is the sole material for the build, even when it is terrain. Name the material in the action bar and show the blinking lone-corner marker of 0183.
5. With point 1 set, preview the end point and shape live. Aimed blocks give the end point; aiming at air gives a virtual point on the vertical plane through point 1 facing the player, snapped to the dominant horizontal look axis. Limit the virtual point to `BUILD_SPEC.touchTapReach` for touch and `BUILD_SPEC.reach` for pointer input. If the plane intersection is beyond that limit, omit the end point and shape outline. Block hits take precedence within the full build reach for either input. Show outlines of the shape and end-point block when an end point is available. A second block tap or an air press with a valid virtual point fixes the base. A line enters the selected state immediately. A rectangle or box enters live height aiming as defined in ADR 0253. A wand press in air or on a block fixes that height without opening a menu. Once selected, a wand press in air or on any block opens the root shape menu at either sneak state.
6. Derive the menu shape from the axes on which the fixed inclusive bounds differ: one gives a line, two a rectangle, and otherwise a box, including coincident endpoints. A one-layer rectangle is horizontal; otherwise it is a wall. Use stable `@minecraft/server-ui` ActionForms with a root menu ordered Adjust height, Cut, Remove above, Build shape, Copy, Fill below, Cancel. Adjust height returns rectangles and boxes to live height aiming (ADR 0253). A line hides Adjust height, replaces Build shape with Place, and needs no submenu. Build shape opens the build submenu: vertical rectangles offer Fill and Frame; horizontal rectangles add Gable roof, Hip roof, Cylinder, Sideways cylinder, Sphere and Cube; boxes offer Fill, Faces only, Walls only, Gable roof, Hip roof, Cylinder, Sideways cylinder, Sphere and Cube. Back is last in the build submenu and returns to the root with the same selection and preview. The root title uses `form.shape_title`; the build submenu title uses `form.build_shape_title`. Back and build submenu dismissal return to the root under one per-player lock across nested forms. Root dismissal keeps the selection and its outline. Root Cancel clears the selection and returns to idle. The root menu is the starting level for a fixed selection; changing menu levels changes no geometry, material, height step, contents menu or Undo behavior.
7. Holding the wand, Paste Rotate, Paste Place, or Build Undo keeps a fixed selection or paste aiming active. Paste Rotate also keeps live height active after the second tap. An unrelated item clears the selection or ends paste aiming after the leave grace period. Changing away from the applicable build items also cancels other in-progress steps after that grace period. Shape builds leave the built box selected and available for Copy. For Place, Fill, Frame, Faces only and Walls only, this is the original box. Undo restores the pre-build box while the result is still selected. Build Undo first reverses a fresh selection step as defined in [0258](0258-build-undo-steps-back-fresh-selection.md). Starting a new point 1, clearing the selection, or leaving paste as specified in 0203 clears the box retained for Copy.
8. A horizontal rectangle or box can start a gable or hip roof. Roof height starts from the selection’s lowest layer (ADR 0201). With stepped roofs, aim to choose the apex on the vertical line through the rectangle's center, at the point nearest the view ray, with the apex layer being the layer that contains that point; preview the outline live and tap to confirm. If the ray is nearly parallel to the line, use the stored height. Cap the aimed height at 300 percent of the long side and the world top. Check the placement count against the 100,000-block edit limit after the player chooses Fill or Hollow. If aiming proves unusable, a slider form is the fallback.
9. A gable ridge runs along the long side. A hip roof slopes inward on both axes. At full inset a square hip ends at one cell for odd spans or a symmetric two-by-two top for even spans. Stair material sets a fixed 45-degree pitch with height `floor((shortSpan - 1) / 2) + 1`. Skip height aiming and refuse a stair roof whose top would exceed the world top. Orient each stair to descend toward its nearest eave and place the odd-span ridge upside down for a flat top. Offer Fill, Hollow, and Cancel once the height is known. Fill orients every stair, and Hollow keeps the shell and gable end walls with an open bottom. A single-layer stair roof stays whole. Other materials form stepped layers of full blocks and Hollow keeps their bottom closed. A flat roof is a horizontal rectangle filled normally.
10. Sneak and tap on air opens a utility ActionForm with only applicable entries: Copy when a selection exists, Paste when a clipboard exists, Undo, and Clear selection. Set Paste's Skip air toggle before aiming. Choosing Paste starts a live clipboard outline at the aimed block; a block tap fixes the anchor and pastes. There is no rotation, and a paste overlapping a protected cell is refused as a whole.
11. Keep the existing protections for vehicle and camp space, laid blocks, and kept blocks. Fill, hollow, roof, and paste take no inventory blocks, and undo returns none, in every game mode. An edit covers at most 100,000 blocks, a copy at most 32,768 blocks, and undo retains at most 10 edits per player. Selections, clipboards, and undo history remain in memory only.
12. Keep stable Script APIs, the existing layer and feature boundaries, and the `@minecraft/server-ui` 2.0.0 dependency. Put pure geometry in the build domain and view-ray reading, forms, and particles in build infrastructure. Add each user-facing step to the manual test, unverified until checked on the iPad.

## Consequences

A player can select, preview, build, copy, paste, undo, and clear with one wand without riding a bulldozer. The first block must be chosen carefully because it also selects the material. Existing Build Tool items disappear, and Replace is no longer available. The new flow needs live previews, shape and roof geometry, and touch verification; stepped roof aiming may require the slider fallback. Stair roofs open the contents form immediately and retain the selected material throughout, including at the ridge. The current size limits and protections still bound edits, while inventory-free edits continue to permit duplication in Survival.
